## 请求示例

先调用`POST /api/v1/auth/login`登录，再在Swagger的Authorize中填写返回的Bearer Token。业务更新使用本次新生成的8—128位可见ASCII幂等键；同一请求重试保持原键，变更请求内容时换新键。

以下ID和版本是初始化快照；执行过更新后，先GET详情读取最新版本再继续。业务错误也可能返回HTTP200，应检查JSON的code字段。

1. 客户详情：`GET /api/v1/enterprise/customer/2`。更新：`PUT /api/v1/enterprise/customer/2`，请求体：

```json
{
  "full_name": "接口测试客户1_已修改",
  "expected_version": 2
}
```

2. 成绩更正：`PUT /api/v1/enterprise/scores/2`，请求体：

```json
{
  "score_value": 95,
  "max_score": 100,
  "reason": "接口测试：模拟成绩更正",
  "expected_version": 1
}
```

3. 学业节点：`GET /api/v1/enterprise/academic-events/2`。用`PUT`修改时传`expected_event_version`（初始1）、带时区的due_at及reason，可查看student_academic_reminder中的提醒同步重排。

4. 工单回应：`POST /api/v1/enterprise/tickets/2/followups`，请求体：

```json
{
  "content": "接口测试：老师已查看反馈，正在跟进。",
  "visibility": "student_visible",
  "expected_version": 1
}
```

5. 日报摘要：`POST /api/v1/enterprise/daily-report/summary`，传`{"report_id":2}`，并提供幂等键。

6. 知识问答：`POST /api/v1/enterprise/onboarding/ask`，传`{"question":"接口测试签到时间是什么？"}`或`{"question":"测试资料提交流程是什么？"}`。

7. 查询与待办：`GET /api/v1/enterprise/todos`、`GET /api/v1/enterprise/notifications`；自然语言查询：`POST /api/v1/enterprise/nl2sql`，传`{"question":"统计我有权限查看的客户总数","filters":{}}`。

### 管理员开户请求示例（待手动执行，不代表已创建）

先POST /api/v1/auth/login取得管理员Bearer Token，随后为注册请求提供Authorization与Idempotency-Key（如register-manager-demo-001）。初始密码由服务端固定，以下请求不包含密码。

新建主管员工与登录账户：
```json
{
  "identity_type": "employee",
  "username": "demo.manager",
  "profile": {
    "employee_no": "REG_MANAGER_001",
    "full_name": "注册测试主管",
    "department_id": 1,
    "position_title": "部门主管"
  }
}
```

新建学生与登录账户：
```json
{
  "identity_type": "student",
  "username": "demo.student",
  "profile": {
    "student_no": "REG_STUDENT_001",
    "full_name": "注册测试学生",
    "department_id": 1
  }
}
```

绑定已有学生：{"identity_type":"student","username":"demo.student.existing","student_id":2}。学生ID须实际存在、active、未归档且未开户；使用前从数据库确认当前状态，不同时提供profile。

新建客户：{"identity_type":"customer","username":"demo.customer","profile":{"full_name":"注册测试客户","department_id":1}}。

新建平台管理员：{"identity_type":"admin","username":"demo.admin"}。不提供employee_id／student_id／customer_id或profile。

新账户创建成功后可通过现有登录接口使用123456登录。员工role_codes由职位生成；学生及客户本人权限由对应档案ID约束。新建档案的主键使用本次返回值，不预设连续ID；验证事务回滚仍可能产生自增ID间隔。职位、学号、工号、用户名等唯一值已使用时需换新值或正确绑定已有档案。
