下面按**实际调用层级**（浏览器 → 前端 → HTTP 接入 → 公共技术约束 → 业务编排 → 数据访问 → 模型 → 外部/本地能力适配）梳理成一张分层流程图，并逐层写清职责。只写层级，不写具体接口细节。

# 二、各层级功能说明

## ① 浏览器 / 用户
- 用户访问 `frontend/index.html` 总入口，按角色进入对应业务页面。
- 不直接接触后端，一切通过前端资源层发起 HTTP 请求。

## ② 前端页面层 `frontend/{common,agent,customer,report,enterprise,student}`
- **common**：`login.html`，登录与公共入口页面。
- **agent**：`agent.html`，客服对话、报名、课程、FAQ 页面。
- **customer**：`customer.html`，客户研判、上传/下载、规则发布与结果查询页面。
- **report**：`report.html`，报告生成、指标查看、权限范围页面。
- **enterprise**：`enterprise.html`，企业助手、日报、知识、通知、NL2SQL 页面。
- **student**：`student-assistant.html`，学生助手、请假、投诉、会话页面。
- 只负责结构与交互，不承载业务规则。

## ③ 前端资源层 `frontend/css/*`、`frontend/js/*`、`frontend/assets`
- **js/common/api.js**：统一请求工具（统一信封、JWT 携带、错误处理）。
- **js/common/app.js**：站点入口、身份状态、路由/页面切换。
- **js/common/charts.js、effects.js**：图表与交互效果公共资源。
- 各业务 `js/{模块}/*.js`：调用 `api.js` 发起对应业务请求，渲染结果。
- `css/*` 按业务分包，`assets` 放静态素材。
- 职责边界：只做请求发起、数据展示、交互状态，不做权限判断与业务计算。

## ④ 应用装配与公共入口层 `app/main.py、config.py、database.py、access_control.yaml`
- **main.py**：唯一应用装配与路由挂载入口，把 ⑤ 各 api 模块挂到应用上。
- **config.py**：唯一配置加载入口（读 `.env`）。
- **database.py**：唯一 `Base`、连接与会话入口，所有模型共用同一 metadata。
- **access_control.yaml**：统一权限与访问策略来源。
- 职责边界：只做装配、配置、连接、策略加载，不写业务逻辑。

## ⑤ HTTP 接入层 `app/api/{common,agent,customer,report,enterprise,student}`
- **common/auth.py**：登录、公开清单、本人权限。
- **agent/agent.py**：客服六接口。
- **customer/customer.py**：研判原 8 接口 + 受控原件下载、force 解析、规则发布与结果查询。
- **report/report.py**：报告五接口。
- **enterprise/enterprise.py**：企业接口与本人通知详情；调用学生协作接口，不重复审批。
- **student/student.py、student_leave.py、student_ticket.py**：学生/老师/同步/受控接管接口；请假与工单只委托唯一服务。
- 职责边界：只做请求接收、参数绑定、依赖注入、调用 core 与 service，不写业务规则。

## ⑥ 公共技术约束层 `app/core/common` + 模块 core
- **common/auth.py**：统一 JWT 身份依赖。
- **common/authorization.py**：权限计算与逐接口校验。
- **common/dify.py**：唯一 Dify HTTP 传输工具。
- **common/logger.py**：日志初始化。
- **common/response.py**：统一信封与异常出口。
- **report/report_auth.py**：报告动作、管理员/主管范围校验。
- **enterprise/enterprise_authorization.py**：员工角色、动作与数据范围；**enterprise_sql_guard.py**：SQL AST 及只读校验。
- **student/student_auth.py**：学生范围、业务凭证及服务身份。
- 职责边界：横切关注点（认证、授权、日志、响应、外部传输、SQL 安全），不承载业务编排。

## ⑦ 业务契约层 `app/schemas/{common,agent,customer,report,enterprise,student}`
- 定义请求、响应与业务契约（Pydantic 模型）。
- 按业务模块分包，与 ⑤ 接入层、⑧ 编排层一一对应。
- 职责边界：只做数据结构与校验约束，不做业务计算。

## ⑧ 业务编排层 `app/services/{common,agent,customer,report,enterprise,student}`
- **common**：`auth_service`（账号密码、JWT 签发解析）、`nl2sql_service`（兼容入口）。
- **agent**：`agent_service` 对话、报名、课程及 FAQ 编排。
- **customer**：`customer_service`、`extractor`、`judge_service`、`parser` 研判编排。
- **report**：`report_anonymizer`、`report_metrics`、`report_service` 报告编排。
- **enterprise**：command、customer、daily_report、knowledge、nl2sql、notification、score、ticket 八类编排。
- **student**：chat、common、knowledge、leave_service（唯一请假服务）、local_query、service、sync、ticket_service。
- 职责边界：业务规则与流程编排，调用 ⑨ 数据访问、⑫ 外部适配、⑬ 异步任务；不直接写 SQL、不直接操作 ORM 会话细节。

## ⑨ 数据访问层 `app/repositories/{common,agent,customer,report,enterprise,student}`
- **common**：account、notification、operation_log 仓储。
- **customer**：统一锁序、批次、savepoint、单条/批量业务幂等。
- **report**：可信范围、请求/业务键、唯一任务及原子发布。
- **student**：leave_repository、schema 检查（开发期结构检查，不在启动建表）、ticket_repository。
- 其余模块按业务提供参数化数据访问与条件更新。
- 职责边界：参数化读写、条件更新、幂等与锁序，不写业务规则。

## ⑩ 模型层 `app/models/{common,agent,customer,report,enterprise,student}`
- **common**：12 张跨模块共享表唯一映射（账号、员工、学生、通知、工单、审计等）。
- **agent**：客服 6 表。
- **customer**：客户信息、来源、产品、研判结果、规则版本。
- **report**：报告三表及拟新增 `report_task`（未部署）。
- **enterprise**：客户跟进、员工日报、知识条目。
- **student**：学生业务表、会话及轮次表、业务枚举与类型。
- 职责边界：ORM/Table 唯一映射，共享表只在 common 声明，业务模块复用，不重复声明 Base/Table。

## ⑪ 数据库
- 共享表 + 各模块独占表。
- 增量由 `scripts/sql/{common,agent,customer,report,enterprise,student}` 管理，`bk/` 仅历史参考，`all.sql` 为初始化基线不自动升级。
- 结构检查脚本在 `scripts/common/check_shared_schema.py`、`scripts/student/check_student_shared_schema.py` 等，开发期核对，不在启动时建表。

## ⑫ 外部/本地能力适配层 `app/clients/{common,agent,customer,report,enterprise,student}`
- **common**：`nl2sql_dify` 兼容适配。
- **agent**：`dify_client` 客服 mock/real 及 Workflow 适配。
- **customer**：`extract_dify` 可选字段抽取。
- **report**：`report_dify`。
- **enterprise**：`enterprise_asr`（本地 faster-whisper）、`enterprise_dify`、`enterprise_nl2sql_dify`。
- **student**：`student_assistant_dify`（当前统一学生应用）、`student_clients`（查询与来源同步适配契约）、`legacy/` 历史参考。
- 职责边界：把外部/本地能力封装成应用协议，统一复用 `core/common/dify.py` 传输；不写业务规则。

## ⑬ 异步任务层 `app/tasks/{report,enterprise,student}`
- **report**：报告定时、持久任务/租约/恢复；外部结果不明不盲重发。
- **enterprise**：enterprise 前缀通知、24 小时轮次、督办及重试。
- **student**：student 前缀通知、接管检查、提醒代次及同步可选分支。
- 职责边界：扫描、调度、领取、重试、租约与恢复，调用 ⑧/⑨ 完成业务，不重复业务规则。

## ⑭ Dify 资产层 `dify/{agent,customer,report,enterprise,student}`
- **agent**：客服知识库与 Workflow（历史文件名，目标为 Workflow）。
- **customer**：研判规则知识库与抽取应用。
- **report**：报告应用。
- **enterprise**：日报、抽取、知识（QA/RAG 一个应用内分支）、只读 NL2SQL；legacy 仅参考。
- **student**：`student_assistant.yml` 唯一学生应用目标，legacy 仅参考。
- 职责边界：应用编排资产与知识库，由 ⑫ 适配层加载调用，不直接连数据库。

# 三、调用链小结（按实际顺序）

```text
浏览器
 → frontend/index.html
 → frontend/{模块}/*.html
 → frontend/js/common/api.js（+ 模块 js）
 → app/main.py 装配路由
 → app/api/{模块}/*.py
 → app/core/common（auth/authorization/response/logger/dify）+ 模块 core
 → app/schemas/{模块}/*.py
 → app/services/{模块}/*.py
 → app/repositories/{模块}/*.py
 → app/models/{模块}/*.py（共享表在 common）
 → database.py 会话 → 数据库
（旁路：services → clients/{模块} → dify/{模块}；tasks 定时/异步调用 services/repositories）
```
