# 留学项目平台前端

登录成功后统一进入 `common/workspace.html` 的“通知中心”：上方公共通知，下方本人消息列表，点击条目查看详情并标记已读。业务模块保留在按权限生成的左侧菜单中，不显示“可用模块”标题及侧栏底部入口；首页姓名入口也返回通知中心。

公共通知支持管理员维护草稿、发布、置顶、有效期和撤回。个人消息复用员工和学生的现有消息及可见范围；客户无实际接收消息时显示空列表。个人已读状态独立保存，不修改业务流程和业务通知表。首次启用须用项目 Python 环境执行 `python -m scripts.migrate_notification_center`，仅新增公告及已读记录两张表，随后重启后端。

首页右下角客服悬浮球按需加载既有客服页面，独立面板仅显示咨询、课程、活动和常见问题。关闭再打开保留当前客服页面，手机端适配抽屉布局。工作区仅平台管理员和具备管理员角色的员工保留客服菜单，其他账号通过首页使用；这只改变入口，不改变客服原有接口权限。客服容器样式和导航位于公共布局，未修改客服业务页面。

个人中心为单层入口，通过 `PATCH /api/v1/auth/me/profile` 保存本人正式姓名，并同步首页与顶部身份。直接更新既有 `employee`、`student_profile`、`customer_profile` 的 `full_name`；平台管理员复用系统现有的管理员员工操作档案。沿用 `row_version`、更新时间及操作日志，不新增表，不修改登录用户名或权限。现有组织和客户修改接口为业务管理授权，无法覆盖学生、客户本人，因此补充此最小的公共本人接口，不放宽管理接口权限。接口拒绝指定其他用户、空姓名和过期修改。

有效部门主管（员工 `manager`）可使用客户信息研判和智能报告的只读入口。报告沿用现有报告授权器，仅读取本人主部门报告；客户研判通过 `customer_info.customer_id` 关联既有客户档案的部门，列表、总数与详情均按同一范围过滤，混合来源的详情只显示本部门客户字段，无法归属部门和已归档客户不向主管展示。规则、产品是无部门字段的公共目录，只读共享。主管不授来源原件下载、上传、解析、执行研判、规则修改、报告生成或配置权限；共享业务布局按精确动作权限筛选表单，接口独立拒绝越权请求。本次无需数据库迁移。

`npm run test:support` 使用虚构账号与响应验证客服聊天和切换、桌面与手机布局、管理员菜单保留、姓名保存失败及成功后刷新和返回首页的同步行为，不写入真实姓名。

`npm run test:workspace` 使用 SQLite 虚构账号和本地 Edge，验证十种身份/岗位组合、模块过滤、撤权、无权限地址拦截与手机布局，不写入真实业务数据。

`npm run test:notifications` 验证公告维护、列表筛选分页、详情、已读状态、业务记录定位及手机布局；公告发布使用虚构接口响应，不写入真实公告。

保留学院风布局，69 个主要页面和 5 个兼容入口现通过真实 API 使用本地 MySQL 业务数据。

在项目根目录运行 `npm run dev`，启动后自动打开 `http://192.168.5.12/login.html`，同一局域网设备可使用该地址访问，无需填写端口或配置域名解析。Vite 监听 HTTP 80 端口，本机也可通过 `http://127.0.0.1/login.html` 访问。账号 `root`、密码 `root`。首次使用局域网访问时，在管理员 PowerShell 中运行根目录的 `scripts/setup-lan.ps1` 配置防火墙。

Vite 配置位于根目录 `vite.config.mjs`，将 `/api`、`/health`、`/openapi.json` 代理到 `127.0.0.1:8000`。`/static/*` 和旧登录/工作台地址兼容原有入口。直接双击 HTML 不能使用业务接口。

业务页面使用 `js/workspace/pages.js` 的资源登记与 `js/workspace/live.js` 的共享表单、表格及响应处理。字段约束来自后端契约；账号管理契约仅在管理员登录后读取。登录令牌只保存在当前标签页；退出时同步清除业务记录选择和确认预览。

读取列表后选择记录，可以回填编号和当前版本；提交失败时保持相同请求的幂等键。提醒更新时间按原始微秒精度回传。上传使用 FormData，支持当前契约中的 contentMediaType 文件描述。模型预览与业务确认分开提交。

没有配置的模型、同步和语音能力显示实际不可用原因；不会返回模拟成功。学生本人业务需要学生身份，管理员可通过账号管理创建。

- `npm run test:frontend`：公共请求、会话、权限、上传、幂等和时区单元测试。
- `npm run test:system`：Edge 浏览器遍历全部页面，并通过 Vite 连接真实后端执行业务表单。先运行后端验收脚本准备带 QA 标识的业务身份。
- 浏览器测试脚本：`scripts/testing/browser-system.mjs`；测试结果及截图写入 `.runtime`。

页面总览为 `common/sitemap.html`；完整系统启动与外部服务后续方案见根目录 README。
