# 企业智能助手接口测试数据

已导入本地 MySQL `127.0.0.1:3306/education_agent`，适配本目录 `企业智能助手_建表.sql` 的独立 14 表模型。共 119 条虚构记录，业务编号为 `EIT-` 前缀，主键从 `910001` 起。

这批数据用于接口开发、查询过滤、权限与状态流转测试。没有创建真实登录账号、发送外部消息或调用 CRM、教务、Dify。

## 1. 文件与重新导入

- [测试数据 SQL](企业智能助手_测试数据.sql)：包含完整事务、数据以及提交前的 24 项校验。
- [生成及导入脚本](../../../../scripts/seed_enterprise_data.py)：从项目根目录执行下列命令。
- [对应建表脚本](企业智能助手_建表.sql)：当前实际数据库使用的模型，不是 `all.sql` 的行政申请模型。

```powershell
# 只生成 SQL，不写数据库
python scripts/seed_enterprise_data.py

# 生成并导入：读取项目根 .env，使用 PATH 中的 mysql 客户端
python scripts/seed_enterprise_data.py --apply
```

本批已导入，无需再次执行。脚本检查保留主键是否占用；重复执行会拒绝写入，不重置已被接口修改的测试记录。普通 INSERT 的唯一键冲突也会使整个事务回滚，不使用 INSERT IGNORE 或覆盖式 upsert。

手工执行 SQL 时必须采用“遇错停止”的方式；发生任何错误应 ROLLBACK 并断开连接，不能让客户端遇错后继续执行 COMMIT。推荐使用 Python 导入脚本，因为它固定以不带 `--force` 的 mysql 客户端执行。

连接有意读取主 `.env`，不读取 `.env.student.local`。若运行 API 时启用了其他端口或库的覆盖配置，需要先确认 API 与这批数据连接的是同一个实例。本脚本不更改任何连接配置。

时间基准使用导入时的 MySQL UTC 时间；日报日期按上海时区计算。待跟进与超时记录相对导入时间生成，后续随时间推移状态仍由接口或任务更新，脚本不会自动刷新。
