# 学生智能助手联调与验收清单

版本：V1.0，2026-10-14。配套《学生智能助手_建表方案.md》《学生智能助手_建表草案.sql》。以下为建议契约与待执行验收用例，不表示这些接口已实现或测试已通过。

## 1. 小组共用边界

| 对接方                   | 必须交付/统一的内容                                              | 学生模块提供                           |
| --------------------- | ------------------------------------------------------- | -------------------------------- |
| 组长/公共能力               | 独立NL2SQL接口地址、请求/响应Schema、鉴权方式、只读账号、行权限、分页/超时、Schema更新方式 | 七张业务表字典、关联关系、业务术语、可信身份、查询场景和返回字段 |
| 身份/基础设施负责人            | student_id/employee_id类型、教师归属、角色范围、鉴权依赖；共享通知/事件是否存在     | 最小身份映射需求，不创建第二套账号和权限系统           |
| 企业助手负责人               | 同一申请/工单/预警ID；调用同一业务service或内部API；审批/分派/跟进UI             | ORM和状态机、事务/幂等服务、统一工单事实源          |
| 报告负责人                 | 心理/投诉统计时间窗、访问范围和指标口径                                    | 画像历史、预警处置时间、投诉类型/分类/响应/解决/评价字段   |
| 教务/CRM适配负责人（可由学生模块承担） | 外部测试接口、学生映射、源ID、源更新时间/版本、取消语义、时间及状态映射                   | 最小节点/阶段镜像、同步任务、stale与更新时间返回约定    |
| 通知基础设施负责人（可复用公共模块）    | 实际渠道、移动端待办入口、幂等/回执、值班兜底和升级规则                            | 通知事务入队、租约重试、业务状态关联               |

以上是对接责任，不指定实际组员姓名；数据事实源、迁移维护人和共用service归属在联调前记录。

## 2. 现有接口修改对照

所有路径以/api/v1为前缀。响应继续使用{code,message,data}，时间使用带时区ISO 8601，学生身份从会话解析。

| 现有接口                         | 当前文档缺口                     | 本次建议                                                                                                                    |
| ---------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| POST /student/leave          | 只有student_id和leave_content | student_id移至可信登录身份；保留leave_content，新加leave_start_at/leave_end_at；Idempotency-Key请求头；返回apply_id、approval_status、version  |
| GET /student/academic        | 单个ddl/exam_time不能表达多节点     | 调用组长NL2SQL；返回events[]，每项含event_id、event_type、title、due_at、source_timezone、synced_at、stale；若保留旧ddl/exam_time则明确为最近一个有效节点 |
| GET /student/progress        | 单个三状态对象不能区分多院校             | 调用组长NL2SQL；返回applications[]，按external_application_id分组，含申请名、各stage_code/stage_status、synced_at、stale                    |
| POST /student/complaint      | 建议不能区分，重试会重复               | 增加feedback_type（默认complaint）；投诉正文继续complaint_content；Idempotency-Key；Dify生成summary/category失败时仍可提交                      |
| POST /student/mental/monitor | 无源消息幂等标识/评估时点              | student_id来自身份；source_event_id和observed_at由可信入口固定；服务调用Dify并验证结果；high/critical创建预警，low/medium的warning_id为null            |
| POST /enterprise/command     | 文档只给自然语言和目标姓名              | Dify解析action和目标ID，存在重名就澄清；Python确定性审批/跟进service；不能通过模型UPDATE执行写操作                                                       |
| POST /enterprise/nl2sql（旧示例） | 不等同于组长拆出的最终接口              | 由组长给出实际独立查询接口；学生模块用适配客户端，不依赖旧示例SQL或返回结构                                                                                 |

请假提交示例：

```http
POST /api/v1/student/leave
Authorization: Bearer <登录凭证>
Idempotency-Key: <客户端固定UUID，重试复用>
Content-Type: application/json

{
  "leave_content": "因病请假",
  "leave_start_at": "2026-10-15T09:00:00+08:00",
  "leave_end_at": "2026-10-16T09:00:00+08:00"
}
```

服务端转换为UTC入库，不把示例日期当固定业务日期。客户端旧字段student_id若暂时保留，必须与身份匹配；不匹配拒绝，不能让它成为实际身份来源。

## 3. 必须补充的业务接口

这些接口补齐已有需求闭环；URI为建议，最终写入小组OpenAPI。查询接口均接组长查询服务，写接口调用固定业务service。

| 方法/建议路径                                              | 目的         | 核心参数和约束                                                                             |
| ---------------------------------------------------- | ---------- | ----------------------------------------------------------------------------------- |
| POST /student/chat                                   | 七类场景学生入口   | message、会话标识；服务可信绑定student_id；Dify意图→查询/写service/RAG；写意图缺参数先澄清                      |
| GET /student/leave/{apply_id}                        | 本人请假状态     | 只查本人的申请；返回状态/时段/审批意见/版本                                                             |
| DELETE /student/leave/{apply_id}                     | 撤销待审批请假    | expected_version、幂等键；仅pending，执行状态更新而非物理删除                                          |
| POST /enterprise/leave/{apply_id}/decision           | 老师审批/驳回    | decision=approved/rejected、comment、expected_version、幂等键；校验老师权限；驳回须理由                |
| GET /student/tickets/{ticket_id}                     | 本人工单进度     | 只查本人，读取统一after_sales_ticket                                                         |
| POST /enterprise/tickets/{ticket_id}/assign          | 工单分派       | follower_id、expected_version、幂等键；管理/分派权限                                            |
| POST /enterprise/tickets/{ticket_id}/follow          | 工单多轮跟进     | note、expected_version、幂等键；首次人工回应写first_response_at；追加action                         |
| POST /enterprise/tickets/{ticket_id}/resolve         | 工单结案       | solution、expected_version、幂等键；当前processing；写resolved_at并通知学生                        |
| DELETE /student/tickets/{ticket_id}                  | 撤销尚未处理的反馈  | expected_version、幂等键；只允许pending状态                                                   |
| POST /student/tickets/{ticket_id}/rating             | 本人对已解决反馈评分 | satisfaction_score 1～5、expected_version、幂等键；追加rate操作，不由AI填分                         |
| GET /enterprise/mental/warnings                      | 授权老师待跟进预警  | 明确负责学生范围；经组长受控查询，不开放学生通用查询                                                          |
| POST /enterprise/mental/warnings/{warning_id}/ack    | 人工接手       | expected_version、幂等键；写acknowledged_at和processing                                    |
| POST /enterprise/mental/warnings/{warning_id}/follow | 追加人工跟进     | note、expected_version、幂等键；心理专属权限                                                    |
| POST /enterprise/mental/warnings/{warning_id}/close  | 人工关闭       | handling_result、expected_version、幂等键；processing→closed                              |
| POST /student/reminders                              | 设置/重新开启提醒  | academic_event_id、lead_minutes；从当前节点计算notify_at/version；本人节点、未取消、提醒时点有效；唯一键幂等upsert |
| GET /student/reminders                               | 查看本人提醒设置   | 由组长查询服务读取；pending/queued/sent/cancelled                                             |
| DELETE /student/reminders/{reminder_id}              | 取消提醒       | 同事务取消设置和当前版本未发送任务；不物理删历史；到点发送并发须验证状态                                                |
| GET /student/notifications                           | 查看本人收件通知   | recipient_type=student且recipient_id=当前学生且status=sent；不能读取发给老师的消息                    |
| POST /student/notifications/{notification_id}/read   | 标记本人消息已读   | 固定UPDATE，必须核验recipient身份；重复调用成功                                                     |

普通状态查询分页；详情查询0条返回404，不自动扩大到其他学生或用姓名模糊匹配。老师预警通知已读独立于ack。

## 4. 组长NL2SQL接口建议契约

以下字段是学生模块所需语义，不是对组长既有请求模型的断言。最终可映射为组长字段名。

| 语义                      | 来源                   | 必需约束                                           |
| ----------------------- | -------------------- | ---------------------------------------------- |
| query/intent            | 用户问句或结构化场景生成问句       | 模型仅生成查询，不能输出写SQL执行                             |
| subject/role/data_scope | Python鉴权上下文或可信服务令牌   | 普通用户/Dify不能伪造role=teacher或换student_id；身份服务负责验证 |
| resource_context        | api解析的申请/工单/节点/申请单ID | 具体ID也必须受行权限约束，不能因有ID就放行                        |
| trace_id                | 服务统一日志链路             | 与请求/错误/查询审计对应                                  |
| allowed_tables/columns  | 服务端按场景选择配置           | 用户可提问，但不能自选心理表、audit和技术字段                      |
| page/limit、timeout      | 服务限制                 | 返回行数有上限、分页与超时可辨别                               |
| rows与查询时间/新鲜度字段         | 组长返回结构化结果            | 不能仅返回难解析的自然语言；业务层核对数据结构与身份                     |
| error_code/错误类别         | 组长统一响应               | 区分非法查询、越权、超时、依赖不可用，不暴露原SQL/凭据                  |

例：GET /student/leave/42传入结构化resource_id=42及登录student_id=7，对查询产生的全部关联和子查询强制本人范围；不能让Dify通过自然语言中的student_id覆盖7。

### 4.1 建议的场景白名单

| 场景                   | 允许事实源/关键字段                                                                           | 行范围                                                  |
| -------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| student.leave        | student_admin_service：id、apply_type、apply_content、approval_status、起止/审批意见及时间、version | student_id=当前学生                                      |
| student.ticket       | after_sales_ticket：id、反馈类型/正文/摘要/类别、状态、solution、响应/结案时间、评分、version                   | student_id=当前学生                                      |
| student.academic     | student_academic_event：id、type、title、due_at、source_timezone、status、synced_at         | 本人节点；按接口场景筛选有效/取消状态                                  |
| student.reminder     | student_academic_reminder与本人学业节点：id、lead_minutes、notify_at、status、sent_at            | 两表均属于当前学生；关联版本一致                                     |
| student.progress     | student_application_progress：申请ID/名、阶段/状态/说明、synced_at                               | student_id=当前学生                                      |
| student.notification | student_notification：id、content、业务关联、sent_at、read_at                                 | recipient_type=student且recipient_id=当前学生且status=sent |
| teacher.mental       | mental_warning、mental_health_profile、受限心理action                                      | 授权负责/分派范围，不能凭通用employee角色开放全体心理数据                    |
| report.mental/ticket | 必要日期/等级/分类/处理时间/评分的聚合                                                                | 批准的数据范围和时间窗；心理个人原文及备注不进入普通周报                         |

student_identity如被查询只能作为本人的业务身份/关联来源；组员姓名、手机号等其他身份数据不因JOIN而被自动开放。history_data、request_key/request_hash、workflow_run_id和通知last_error默认排除普通查询。全库信息schema不能作为用户查询表。

### 4.2 给组长的业务术语

| 用户说法         | 结构化含义                                                                 |
| ------------ | --------------------------------------------------------------------- |
| 我的请假/审批状态    | student_admin_service，apply_type=leave，approval_status                |
| 待审批/已通过/驳回   | pending/approved/rejected                                             |
| 我的投诉/建议      | after_sales_ticket.feedback_type=complaint/suggestion                 |
| 已解决/处理中      | after_sales_ticket.process_status=resolved/processing                 |
| 论文截止/DDL     | student_academic_event.event_type=ddl，due_at                          |
| 考试时间         | event_type=exam，due_at                                                |
| 提前一天提醒       | lead_minutes=1440；以UTC节点时间减提前量                                        |
| 文书审核/院校申请/签证 | stage_code=document_review/school_application/visa_process；按申请ID分组    |
| 最近一周情绪趋势     | mental_health_profile按observed_at范围排序/聚合，授权范围内使用                      |
| 已读预警/已处理预警   | notification.read_at、warning.acknowledged_at、warning.closed_at是三个不同事实 |

## 5. Dify输出与传统后端契约

| AI任务   | 最小结构化输出                                             | 后端职责                                                                       |
| ------ | --------------------------------------------------- | -------------------------------------------------------------------------- |
| 意图路由   | 七场景之一、置信度、缺少的必要参数                                   | 选择明确service；不接受任意表/SQL/他人身份；参数不足先澄清                                        |
| 请假意图抽取 | 理由、明确的开始/结束（缺失则标缺）                                  | 时区/时间校验、学生确认、固定写入；相对日期按用户当前时区解析                                            |
| 心理分析   | emotion_tag、emotion_score、risk_level、trigger_reason | 分值0～100且高分表示较平稳；与风险独立；source_event_id/observed_at由可信源确定；high/critical事务落预警 |
| 投诉摘要   | summary、category                                    | 仅辅助；保留原文；无结果时summary=NULL/category=other，不阻断投诉                             |
| 生活支持   | reply、来源/地区/引用                                      | Dify知识库RAG，API不另建向量切片副本                                                    |
| 升学推荐   | 项目引用、推荐话术、明确意向                                      | 对照有效升学资料/已有项目事实；心理预警和投诉处理中不插入营销；需要长期线索跟进时再复用意向客户模块                         |

workflow_run_id用于排查本次工作流运行，analysis_version由小组发布配置提供。API Key仅在config/安全环境配置读取。Dify HTTP工具若调用写API，需要可信工具鉴权和源事件绑定，不能开放匿名写接口，也不能信任工具请求正文中的student_id。

心理风险是辅助识别与人工工作流，不在数据库方案中编写医学诊断阈值。高危策略、值班人、处理时限由业务流程明确。

## 6. 数据库与端到端待执行验收

| 编号        | 用例                                    | 预期结果                                                    |
| --------- | ------------------------------------- | ------------------------------------------------------- |
| DB-01     | 在空白测试库执行DDL；SHOW CREATE TABLE对照       | 表、列、注释、索引、外键、CHECK均一致；不依赖应用自动建表                         |
| DB-02     | 同名旧表结构不完整时再次初始化                       | 报表已存在；使用显式迁移，不能误判字段已更新                                  |
| DB-03     | 学生A节点给学生B建提醒；A画像挂B预警                  | 组合外键拒绝；service也拒绝越权关联                                   |
| DB-04     | 不存在学生、请假结束早于开始、分值>100、非法状态            | 外键/CHECK或API校验拒绝，无半条关联数据                                |
| DB-05     | 未解决工单评分、已结案但无解决方案、已关闭预警无人工结果          | 约束和service拒绝；空白字符串也由service检查                           |
| ID-01     | 客户端student_id改为别人；Dify伪造老师身份          | 401/403或统一业务错误，无查询/写入越权                                 |
| LEAVE-01  | 正常请假→老师审批→学生通知                        | 主表正确、两端同ID、动作可追溯、通知sent有回执时间                            |
| LEAVE-02  | 同一学生同幂等键提交两次；同键改内容                    | 一条申请；相同内容返回原ID，不同内容409                                  |
| LEAVE-03  | 两老师/重复请求同时审批同一pending版本               | 仅一次条件UPDATE成功；另一请求冲突或确定的幂等回放，不双发结果                      |
| LEAVE-04  | 错误老师审批；缺少责任老师提交                       | 拒绝审批/明确配置错误，不创建无法路由的普通申请                                |
| TICKET-01 | 投诉与建议分别提交；Dify摘要超时                    | 类型区分；原文保留；摘要NULL仍创建工单                                   |
| TICKET-02 | 多轮跟进→结案→本人评分                          | first_response_at仅第一次写；resolved_at明确；action保留各轮；未评分不被填0 |
| TICKET-03 | 企业处理后学生/报告查询                          | 读到同一after_sales_ticket；不存在另一份可写投诉副本                     |
| MENTAL-01 | 同一源消息重复回调/重试                          | 一条画像、最多一条高危预警及对应首发通知                                    |
| MENTAL-02 | 两条独立消息分别评估                            | 两条历史记录，即使学生相同也不覆盖；observed_at可用于周报                      |
| MENTAL-03 | Dify失败、非法risk_level/分值                | 明确不可用/校验错误，不伪造low或无风险                                   |
| MENTAL-04 | 高危且没有归属老师                             | 预警和未路由通知保留，兜底/升级流程可见；不能因为缺负责人丢事件                        |
| MENTAL-05 | 老师只阅读通知，尚未接手/关闭                       | read_at变化不使预警closed；授权人员接手后才写acknowledged_at            |
| SYNC-01   | 同一个外部节点/阶段重复同步；旧事件后到                  | 唯一键upsert不新增重复；旧数据不覆盖新版本                                |
| SYNC-02   | 教务/CRM不可用                             | 保留上次成功数据/synced_at并返回stale；不声称已更新或编造进度                  |
| SYNC-03   | 一个学生两所院校、各三阶段                         | 查询按申请分组，不被三列对象压成一个申请                                    |
| REM-01    | 同节点同提前量重复设置，两种提前量                     | 同提前量只有一条设置，不同提前量可共存                                     |
| REM-02    | 先设置提醒，再修改DDL/取消节点                     | 新版本重排/取消；旧版本待发送任务作废；旧回执不能标记新版本sent                      |
| REM-03    | 学生海外时区、夏令时前后节点                        | 转UTC后按准确时点发送；来源时区正确展示，不按服务器本地时区猜日期                      |
| NOTIFY-01 | 业务提交后渠道失败                             | 业务结果保留，通知可重试，不再次审批/结案                                   |
| NOTIFY-02 | 派发进程领取后崩溃；发送后回写前超时                    | 租约超时恢复；复用事件幂等；记录可能重复投递的真实边界                             |
| NOTIFY-03 | 学生查询本人所有业务通知                          | 只能收到发给本人的sent通知，不能看到同student_id发给老师的预警                  |
| NL-01     | 通过JOIN/子查询/UNION查其他学生、读心理或技术字段        | 组长服务拒绝/强制权限；结果与列均满足场景白名单                                |
| NL-02     | 模型生成INSERT/UPDATE/DELETE/DDL或NL2SQL超时 | 只读账号/安全闸门拒绝写入；超时统一错误，不绕过组长服务                            |
| BASE-01   | 参数校验、业务异常和未知异常                        | 全部统一{code,message,data}，HTTP与业务码符合小组契约，日志无敏感原文          |
| REPORT-01 | 统计心理历史、投诉分类/响应/解决/满意度                 | 可按时间窗复算；建议不算投诉；满意度仅统计真实已评价，说明样本数                        |
