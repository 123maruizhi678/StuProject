# 学生助手：企业侧接口交接

日期：2026-10-15。提供给企业助手负责人。只需接企业端页面和调用这些接口；请假、预警的业务规则由学生模块固定服务执行。企业工单处理、成绩、客户等其他模块仍由原负责人实现。

## 可直接使用的文件

- 学生助手_企业侧_OpenAPI.json：13个企业协作接口及请求Schema，导入Apifox/Swagger。
- 学生助手_企业侧_Postman.json：可导入的请求集合；填写base_url、employee_token、service_token及实际记录ID。
- 学生助手_OpenAPI.json：全部34个学生与内部协作接口。

本机联调地址为http://127.0.0.1:8010，Swagger在/docs。本轮数据库是本机127.0.0.1:3307的独立education_agent；组长数据库不再作为当前写入目标。跨电脑联调时由部署方提供可达API地址。

## 鉴权与响应约定

所有接口要求Authorization: Bearer <JWT>。老师使用employee身份，后端检查employee.status=active、role_codes含teacher、当前有效class_teacher关系及记录实际负责人。前端不能通过student_id/employee_id参数冒充身份。服务同步接口要求service身份与student:sync权限。

JWT为HS256：iss取STUDENT_TOKEN_ISSUER（默认stuproject），aud=student-api，iat/exp为Unix秒。员工Claims包含actor_type=employee、actor_id=员工内部主键；服务Claims包含actor_type=service、service_code=受控服务编码、scopes=[student:sync]。由可信后端签发，签名密钥不发给前端。生产统一登录未接入前，只能在本地用scripts/student_token.py调试。

统一响应：HTTP200，业务code=0成功；400参数错误、401凭证无效、403无权限、404不存在、409状态/版本/幂等冲突、503依赖不可用。企业前端必须判断响应体code，不能只判断HTTP状态。

所有POST需要Idempotency-Key（8至128位可见ASCII）；同一次提交重试复用原键，新动作换新键。Postman中的idempotency_key变量需自行设置；同键换参数会返回409。GET不需要该请求头。

时间用UTC的ISO8601；请求也可携带+08:00等明确偏移。所有列表支持limit=1..100、offset>=0，返回data.items、total、limit、offset。版本读取真实响应，冲突后重新获取详情并让用户确认，不能自动覆盖。

## 公共请假接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/v1/internal/student/leave?status=submitted | 当前老师负责的请假列表；status可省略或取submitted/approved/rejected/withdrawn |
| GET | /api/v1/internal/student/leave/{apply_id} | 当前老师负责的请假详情与row_version |
| POST | /api/v1/internal/student/leave/{apply_id}/decision | 批准或驳回 |

学生侧POST /api/v1/student/leave创建公共student_leave_request记录；返回的apply_id就是数据库leave_request_id。查询详情中的leave_request_id、request_no、reason、start_at/end_at、status、row_version可直接用于企业页面，不另建一张企业请假表。

审批请求示例：

~~~http
POST /api/v1/internal/student/leave/1/decision
Authorization: Bearer <老师Token>
Idempotency-Key: leave-decision-demo-001
Content-Type: application/json

{"expected_version":1,"decision":"approved","comment":"同意请假"}
~~~

成功：

~~~json
{"code":0,"message":"success","data":{"apply_id":1,"approval_status":"approved","row_version":2}}
~~~

驳回传decision=rejected，comment必填，最多2000字。仅submitted可以审批；批准/驳回后不能再次审批或由学生撤回。学生撤回接口DELETE /api/v1/student/leave/{apply_id}需要expected_version，状态改为withdrawn，保留记录。

审批事务同时写decision_employee_id、decision_at、decision_comment、row_version+1、operation_log及学生结果通知；企业端无需再更新表或重复发同一结果通知。事务失败整体回滚。无有效班主任时学生提交仍保存、assignment_pending=true，后台任务后续补分派，老师审批前须读取最新版本。

## 心理预警协作接口

| 方法 | 路径 | 请求体/用途 |
|---|---|---|
| GET | /api/v1/internal/student/warnings?status=pending | 本人授权范围；状态pending/processing/closed |
| GET | /api/v1/internal/student/warnings/{warning_id} | 预警详情，返回row_version |
| POST | /api/v1/internal/student/warnings/{warning_id}/ack | {"expected_version":1,"note":"已接手"} |
| POST | /api/v1/internal/student/warnings/{warning_id}/follow | {"expected_version":2,"note":"已联系并跟进"} |
| POST | /api/v1/internal/student/warnings/{warning_id}/close | {"expected_version":3,"note":"已完成人工跟进"} |

状态流转：pending → ack后processing → follow保持processing → close后closed。每次动作校验版本并递增；note必填，最多2000字。关闭前必须接手。physical字段mental_warning.version通过API统一称为row_version。

预警详情、原因和处置备注只展示给授权老师，不转发到学生通用接口或普通员工日志。读通知不等于接手预警；消息已读不能把预警标为closed。兜底老师只有明确配置STUDENT_FALLBACK_EMPLOYEE_ID才生效。

## 企业侧学生业务通知

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/v1/internal/student/notifications | 当前老师已投递的学生业务站内通知 |
| POST | /api/v1/internal/student/notifications/{notification_id}/read | 本人已读，空请求体，带幂等键 |

仅返回business_notification中student.前缀、employee_id=当前老师、channel=in_app、delivery_status=sent的消息。学生模块任务只处理自己的student.消息；企业其他公共通知任务应避免重复消费这些消息。站内sent不代表微信/短信等外部渠道已送达。

## 教务/CRM服务同步

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/v1/internal/student/sync/academic | 推送学生学业节点，AcademicBatch |
| POST | /api/v1/internal/student/sync/progress | 推送申请阶段，ProgressBatch |
| POST | /api/v1/internal/student/sync/{kind}/pull | 从已配置来源拉取，kind为academic/progress，body={"student_id":1} |

服务凭证专用，不能用老师Token代替。每批最多500条，按source_system+外部对象ID去重，旧source_updated_at不覆盖新数据；同来源时间内容冲突返回409。完整字段与样例模型见OpenAPI。

教务来源GET参数及回显字段为external_student_id，对应student_profile.external_student_id；CRM则为crm_student_id，对应独立CRM身份。不能按姓名匹配或混用两个外部ID。source_system仅允许ASCII字母、数字及_.:-。

## 投诉工单的交接边界

学生侧已实现提交、补充、确认解决/重开、评价。双方复用service_ticket及service_ticket_record。企业端分派/处理/给出方案由企业负责人实现，本交付没有虚构对应HTTP接口。

企业把工单转入awaiting_student时应在自己的固定事务中设置solution、resolved_at、row_version+1并写student_visible处理记录、结果通知；学生随后带最新expected_version确认。不要直接设closed替代学生确认。学生确认未解决会重开工单并重新计算当前轮次SLA。

## 返回字段速查

统一信封之外，data结构如下；业务ID均为整数，空值保留为null。

| 接口 | data |
|---|---|
| 请假列表 | items[]、total、limit、offset |
| 请假详情/列表项 | leave_request_id、request_no、student_id、leave_type、start_at、end_at、reason、attachment_key、approver_employee_id、status、submitted_at、decision_employee_id、decision_at、decision_comment、created_at、updated_at、row_version |
| 请假审批 | apply_id、approval_status、row_version |
| 预警列表 | items[]、total、limit、offset |
| 预警列表项 | id、student_id、profile_id、trigger_reason、risk_level、follower_status、follower_id、acknowledged_at、closed_at、handling_result、created_at、updated_at、row_version |
| 预警详情 | id、student_id、trigger_reason、risk_level、follower_status、follower_id、acknowledged_at、closed_at、handling_result、created_at、row_version（按受控查询白名单返回） |
| 预警接手/跟进/关闭 | warning_id、row_version |
| 通知列表 | items[]、total、limit、offset |
| 通知列表项 | notification_id、entity_type、entity_id、event_code、title、content、sent_at、read_at |
| 通知已读 | notification_id、read=true |
| 同步/来源拉取 | updated、ignored_stale |

risk_level为high/critical；follower_status为pending/processing/closed。预警详情中的部分可空字段可能因组长服务返回范围省略，企业页面须允许缺省，不推断处置状态。精确请求校验以OpenAPI为准。
