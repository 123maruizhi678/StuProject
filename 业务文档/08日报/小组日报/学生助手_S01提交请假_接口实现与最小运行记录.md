# 学生助手 S01 AI辅助请假提交 接口实现与最小运行记录

日期：2026-10-15。负责人：蒋立建。模块：学生助手。

本轮交付一个带Dify调用的最小功能：请假理由摘要和审批关注点生成，再保存本人请假申请。代码和完整DSL已完成，真实模型联调待完成。

## 接口与参数

POST /api/v1/student/leave；权限沿用组长student.admin_service.create。登录/JWT仍由组长负责，本模块取得account.student_id后执行业务归属校验。

请求头：Idempotency-Key，1至128位ASCII字母数字和 . _ : -，首位为字母或数字。正式Bearer凭据由组长公共入口校验，不转发给Dify。

请求体示例：

    {
      "leave_content": "因身体不适申请请假",
      "leave_type": "sick",
      "leave_start_at": "2026-10-20T09:00:00+08:00",
      "leave_end_at": "2026-10-20T18:00:00+08:00"
    }

leave_content去除首尾空白后1至5000字符；leave_type默认personal，1至32字符；起止必须带时区，结束晚于开始。请求体拒绝student_id、reviewer_id和approval_status等额外字段。

成功返回code/message/data；data包含apply_id、approval_status=pending、reviewer_id、row_version、assignment_pending、notification_queued及ai_analysis。

ai_analysis包含summary、review_points、workflow_run_id、analysis_version。模型只生成摘要和人工关注点，不决定审批状态，不替换学生填写的日期和原文。兼容历史幂等回执时ai_analysis可以为null；新申请必须成功完成工作流分析。

## Dify和数据库

专用配置在本机.env.student.local：STUDENT_DIFY_LEAVE_BASE、STUDENT_DIFY_LEAVE_KEY、STUDENT_DIFY_LEAVE_TIMEOUT、STUDENT_DIFY_LEAVE_VERSION。具体导入、选择模型、发布与输出契约见dify/student_leave/README.md。项目现有的NL2SQL Key不能作为本功能Key使用。

工作流调用POST {BASE}/workflows/run，blocking模式，四个请假输入。只接受succeeded及合法result。缺少Key或超时/网络失败返回503；工作流HTTP异常或非法输出返回502；这些失败都不新建业务记录。

正式数据库通过app/database.py的get_db → SessionLocal → MySQL engine，使用公共.env配置。目前目标为127.0.0.1:3306/education_agent，本轮不连接或修改该业务库。

| 读写 | 表 | 内容 |
|---|---|---|
| 读 | student_profile | 本人档案状态 |
| 读 | student_staff_binding、employee | 有效班主任关系与老师资格 |
| 写 | student_admin_service | 原文、UTC时段、pending、负责人；edu_related_data.ai_analysis保存AI结果 |
| 写 | business_notification | 有老师时创建pending站内通知，不代表送达 |
| 读写 | operation_log | 幂等、必要审计及稳定回执 |

没有老师时保留申请并返回assignment_pending=true；本轮不新增自动补分派或实际投递任务。数据库事务失败整体回滚。正式表仍由组内公共SQL/迁移负责，字段投影只在测试库create_all。
