# 学生助手 S01 提交请假接口实现与最小运行记录

日期：2026-10-15。模块：学生助手。功能：S01 学生提交请假。

本次只完成截图中的提交请假接口，不扩展其他20个学生接口。登录、JWT和公共权限判断由组长提供；学生接口只接收公共依赖返回的可信账号，处理自己的业务。

## 一 需求和本次完成内容

对应《学生智能助手》需求文档2.1第1项行政服务、3.2.2审批闭环和第六章第1项。完成闭环中的“学生本人提交—公共表写入—有效班主任分派—待办通知入队”这一段。老师审批、结果查询和通知实际投递不计入本次完成范围。

新版公共表以 `scripts/sql/all.sql` 的 `student_admin_service` 为准；本次不重建表、不另建旧版 `student_leave_request`，不执行全库DROP脚本。

## 二 接口定义

| 项目 | 内容 |
|---|---|
| 方法与路径 | `POST /api/v1/student/leave` |
| 功能编号 | S01 |
| 功能名称 | 学生提交请假 |
| 可访问主体 | 组长统一入口已认证并授权的学生 |
| 公共权限 | `student.admin_service.create`，复用组长现有 `require_permission` |
| 本模块检查 | 学生身份、可信student_id对应档案、未归档且未禁用、时间合法、有效班主任关系 |
| 幂等请求头 | 必填 `Idempotency-Key`，1至128位英文字母/数字及 `. _ : -`；首位为英文字母或数字 |
| 身份来源 | 公共依赖返回的 `account.student_id`；不使用 `account.user_id` 当学生主键 |

正式调用的Bearer凭据按组长统一入口传入。本模块没有登录接口、不生成Token、不复制JWT校验。

### 请求体

```json
{
  "leave_content": "因身体不适申请请假",
  "leave_type": "sick",
  "leave_start_at": "2026-10-20T09:00:00+08:00",
  "leave_end_at": "2026-10-20T18:00:00+08:00"
}
```

| 字段 | 规则 |
|---|---|
| leave_content | 必填；去除首尾空白后1至5000字符 |
| leave_type | 可选，默认personal；1至32字符，当前不增加组内尚未约定的分类枚举 |
| leave_start_at | 必填；必须带时区；落库转为UTC |
| leave_end_at | 必填；必须带时区，并晚于开始时间 |

请求体不允许 `student_id`、`reviewer_id`、`approval_status` 等额外字段，避免客户端代他人提交或指定审批结果。

### 成功回执

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "apply_id": 1,
    "approval_status": "pending",
    "reviewer_id": 11,
    "row_version": 1,
    "assignment_pending": false,
    "notification_queued": true
  }
}
```

这里的ID是隔离测试数据。`pending`沿用新版公共表状态；旧设计中的`submitted`不能直接作为新版物理状态写入。`notification_queued=true`只表示通知已入队，不表示已送达老师。

找不到有效班主任时仍保留申请，返回 `reviewer_id=null`、`assignment_pending=true`、`notification_queued=false`，由后续业务安排分派。本次没有新增补分派任务。

### 错误表现

| HTTP状态 | 场景 | 返回约定 |
|---|---|---|
| 200 | 新申请成功或相同请求重试 | code=0及稳定回执 |
| 401/403 | 公共入口未认证或缺少权限 | 组长统一入口的错误格式，本模块不重写 |
| 403 | 非学生、档案不存在/归档/禁用等 | 本模块code/message/data错误信封 |
| 409 | 同一幂等键不同参数，或数据库关联冲突 | 本模块错误信封；不产生半笔业务 |
| 422 | 缺字段、无时区、结束早于开始、伪造额外字段、请求键非法 | FastAPI标准detail校验错误 |

S01保留真实HTTP状态，不将所有错误改为HTTP200。启动入口中的旧学生OpenAPI重写已跳过此接口，避免文档隐藏422/409。

## 三 业务处理流程

```text
组长可信账号与公共权限依赖
  → 学生模块读取account.student_id并检查学生档案
  → 参数规范化和UTC转换
  → 幂等键与参数摘要检查
  → 找有效class_teacher关系及active且具有teacher业务资格的员工
  → 同一事务创建公共请假、待发送通知和操作回执
  → 提交事务，返回申请ID与待审批状态
```

分派优先主要班主任，再按绑定记录ID确定顺序；排除失效/未生效关系、停用员工和没有teacher资格的员工。本人归属、老师关系属于学生业务校验，不是另做一套登录鉴权。

相同学生、动作和请求键对应唯一操作键；相同参数重试返回原回执，不增加申请或通知。相同键不同参数返回409。内容中的等价时区会先统一成UTC，所以同一时段不会因时区写法不同被误判为不同请求。

写入通知失败时，申请和操作记录一起回滚。操作审计只保留必要状态和负责人，不额外复制请假原文到通知或审计快照。
