# 学生助手：数据表与接口简要说明

日期：2026-10-15。供学生模块汇报及企业侧对接使用。范围为学生模块后端、五张专属表与公共请假表；当前通过API联调，不含网页。

## 一、六张主要业务表

| 表名 | 中文名称 | 主要保存内容 | 两端如何使用 |
|---|---|---|---|
| mental_health_profile | 学生心理评估历史表 | 学生ID、情绪标签/分值、风险等级、评估时间、来源事件 | 学生服务保存每次评估，作为预警与历史分析依据；心理数据仅向授权范围提供 |
| mental_warning | 心理预警及处置表 | 评估ID、学生ID、触发原因、处理老师、处置状态、结果、version | 学生服务生成预警，企业侧授权老师接手、跟进和关闭 |
| student_academic_event | 学业节点表 | DDL/考试、标题、截止时间、来源时区、节点状态与版本 | 同步教务节点，供学生查询及计算提醒时间 |
| student_academic_reminder | 学业提醒表 | 学生ID、节点ID、提前分钟数、计划时间、提醒状态 | 学生设置/取消提醒，后台任务按节点有效版本发送 |
| student_application_progress | 申请进度表 | 外部申请ID、申请名称、文书/院校/签证阶段、当前状态、同步时间 | 同步CRM快照，供学生查看各申请的阶段进度 |
| student_leave_request | 公共请假表 | 请假时段/原因、审批老师、审批状态/意见、row_version | 学生提交/撤回，企业老师审批；双方操作同一条记录 |

六张是本轮学生交付的主要业务表数量，运行还复用下列公共表：

| 复用公共表 | 作用 |
|---|---|
| student_profile、employee、student_staff_binding | 学生/员工真实身份，以及当前班主任或顾问关系 |
| service_ticket、service_ticket_record | 投诉建议工单及沟通处理记录，学生与企业共享处理结果 |
| business_notification、operation_log | 站内通知、操作审计及重复请求回执 |

请假流程：submitted（待审批）→ approved（批准）/ rejected（驳回）/ withdrawn（学生撤回）。仅待审批可以审批或撤回。API中的apply_id即公共表leave_request_id。

预警流程：pending（待接手）→ processing（处理中）→ closed（人工关闭）。物理字段version在API中统一返回row_version。

## 二、学生端接口概览

路径前缀：/api/v1/student。学生身份从登录Token读取，只操作本人数据。

| 功能 | 主要接口 | 简要作用 |
|---|---|---|
| 请假 | POST /leave；GET /leave、/leave/{apply_id}；DELETE /leave/{apply_id} | 提交、查询和撤回请假，共4个接口 |
| 投诉建议 | POST /complaint；/tickets相关查询、reply、confirm、rating接口 | 提交、查进度/沟通记录、补充、确认解决或重开、评价，共7个接口 |
| 心理评估 | POST /mental/monitor | 调用心理工作流，保存评估，符合条件时生成预警 |
| 学业与提醒 | GET /academic；POST/GET /reminders；DELETE /reminders/{reminder_id} | 查询节点、设置/查看/取消提醒，共4个接口 |
| 申请进度 | GET /progress | 查询各申请的文书、院校、签证阶段 |
| 消息通知 | GET /notifications；POST /notifications/{notification_id}/read | 查询本人已送达通知、标记已读 |
| 智能对话 | POST /chat；POST /actions/confirm | 七场景分流；办理动作先预览，学生确认后执行 |

学生端共21个接口，精确请求字段见学生助手_OpenAPI.json。

## 三、提供给企业侧的13个接口

以下路径统一加前缀 /api/v1/internal/student。前10个由企业侧授权老师调用，后3个由有同步权限的服务调用。

| 方法 | 接口路径 | 简要作用 | 主要参数 |
|---|---|---|---|
| GET | /leave | 查看当前老师负责的请假列表 | status可选、limit、offset |
| GET | /leave/{apply_id} | 查看请假详情及当前版本 | apply_id |
| POST | /leave/{apply_id}/decision | 批准或驳回请假，通知学生 | expected_version、decision、comment；驳回必须有意见 |
| GET | /warnings | 查看授权学生的心理预警 | status可选、limit、offset |
| GET | /warnings/{warning_id} | 查看预警依据、负责人及处置状态 | warning_id |
| POST | /warnings/{warning_id}/ack | 老师接手预警 | expected_version、note |
| POST | /warnings/{warning_id}/follow | 记录人工跟进 | expected_version、note |
| POST | /warnings/{warning_id}/close | 填写处置结果并关闭 | expected_version、note；必须先接手 |
| GET | /notifications | 查询当前老师已送达的学生业务通知 | limit、offset |
| POST | /notifications/{notification_id}/read | 标记本人通知已读 | notification_id，空请求体 |
| POST | /sync/academic | 推送教务学业节点快照 | student_id、source_system、records |
| POST | /sync/progress | 推送CRM申请阶段快照 | student_id、source_system、records |
| POST | /sync/{kind}/pull | 主动拉取已配置的来源数据 | kind=academic/progress；请求体student_id |

## 四、调用时记住这几条

- 所有接口带Authorization: Bearer <Token>。老师须有有效teacher角色及对应学生的当前负责关系；同步服务须有student:sync权限。
- 所有POST及学生DELETE带Idempotency-Key：同一次提交重试复用原键，新动作使用新键。
- 审批、工单版本操作和预警处置传expected_version，使用详情返回的真实版本。冲突后刷新并重新确认。
- 响应为{code,message,data}，HTTP沿用200约定；code=0成功，400参数、401身份、403权限、404不存在、409冲突、503依赖不可用。
- 列表返回items、total、limit、offset；时间为UTC。心理预警原因与处置备注仅限授权老师查看。

企业端调用公共请假审批接口即可，服务会在同一事务保存审批结果、操作记录和学生通知；无需再重复改表或发同一结果通知。企业工单处理仍由企业负责人实现自己的服务，学生侧读取同一共享工单结果。

## 五、当前状态及材料

本地数据库为127.0.0.1:3307 / education_agent；本机API文档：http://127.0.0.1:8010/docs。该地址只在本机有效，跨电脑对接由部署方提供可达地址。

本地已验证请假提交→企业审批→学生查询结果/收到通知。学生Dify、组长NL2SQL、真实教务/CRM及企业页面仍需各自环境配置与联调。

- 学生助手_企业侧对接.md：完整对接约定及请求示例。
- 学生助手_企业侧_OpenAPI.json：企业侧接口模型，可导入Apifox/Swagger。
- 学生助手_企业侧_Postman.json：可直接导入的13个请求。
- 学生助手_企业侧交接.zip：包含本说明及上述三份交接材料。
