# 学生助手接口与身份权限清单

> 版本：V1.0；日期：2026-10-15。
> 范围：学生助手全部34个路由定义，学生端21个、老师协作端10个、服务同步端3个。
> 目的：明确每个接口的功能、请求、访问身份、所需权限、数据范围及统一鉴权接入责任，供组长和企业侧审阅。
> 状态：现有路由及业务检查已按源码核对；本文的细粒度权限为统一接入目标，不表示已全部配置或启用。本次仅新增方案文档。
> 格式参考：[客服Agent接口鉴权方案](客服Agent/客服Agent接口鉴权方案.md)。

## 一、模块范围与接口现状

### 1.1 功能范围

| 功能 | 覆盖内容 | 对应接口 |
|---|---|---|
| 学生请假 | 本人提交、查询、撤回；老师查看及批准/驳回 | S01—S04、T01—T03 |
| 投诉与建议 | 原文提交、进度/沟通记录查询、补充、确认解决或重开、评分 | S05—S11 |
| 心理关怀 | 辅助评估、高风险预警；授权老师查看、接手、跟进、关闭 | S12、T04—T08；S20也会产生辅助评估 |
| 学业节点与提醒 | 本人DDL/考试查询，提醒设置/查看/取消 | S13—S16、M01/M03 |
| 留学申请进度 | 按申请ID区分文书、院校、签证阶段 | S17、M02/M03 |
| 海外生活支持 | 通过对话检索真实海外生活资料，返回引用 | S20，life意图 |
| 升学项目咨询 | 通过对话检索真实项目资料，提供有依据的信息 | S20，upgrade意图 |
| 业务通知与确认 | 学生/老师各收各的通知，AI办理先预览后确认 | S18—S21、T09—T10 |

生活和升学通过聊天入口承载，不虚构额外的/life或/upgrade独立接口。企业工单分派、处理、提出解决方案属于企业负责人模块；本文件只列学生侧确认与反馈，以及学生模块拥有的协作接口。

### 1.2 当前实现与目标方案的区别

| 项目 | 当前本地实现 | 本方案目标 |
|---|---|---|
| 身份入口 | 学生路由仍调用app/core/student_auth.py中的get_principal，使用旧学生自签身份凭证 | 接组长统一鉴权，学生不再自行签发/验证登录JWT |
| 业务授权 | 已有本人归属、teacher资格、有效绑定、当前负责人、同步scope、版本与状态检查 | 保留这些检查，再叠加下文明确的接口权限 |
| 权限策略 | app/access_control.yaml只有部分学生相关权限；require_permission尚未接入学生路由 | 与组长确认并补齐权限，再逐接口接入 |
| 应用挂载 | 当前main.py未实际挂载学生及内部协作路由，认证路由也尚未挂载 | 统一入口完成注册后，才以/docs和真实请求验收 |
| 运行配置 | 当前config.py缺少Field导入及认证/学生配置声明，不能据此认定新版本可运行 | 公共配置、依赖与学生配置补齐后再启动联调 |
| 外部能力 | Dify目录现有提示词/输出约束；真实Dify、受控查询、教务/CRM需配置 | 用真实服务验证结果，不将模拟输出当作发布验收 |

接口路径以app/api/student.py的定义为准。本文列出的34个路径是接口设计/路由定义清单，不代表当前启动入口已全部可访问。

## 二、身份主体与可访问功能

### 2.1 身份映射

| 主体 | 统一身份/来源 | 映射到学生模块 | 必须满足的额外条件 |
|---|---|---|---|
| 已登录学生 | user_account.identity_type=student | account.student_id → Principal(student, student_id) | 对应学生主档存在、未归档且业务状态可用 |
| 负责老师 | user_account.identity_type=employee | account.employee_id → Principal(employee, employee_id) | 有效员工；现有业务要求role_codes含teacher；再检查负责关系/当前分派 |
| 普通员工/服务顾问 | identity_type=employee | 真实employee_id | 不因employee身份或顾问绑定自动获得老师接口；企业自己的处理能力按企业方案 |
| 系统管理员 | identity_type=admin | 统一账号身份 | 当前只有admin.dashboard，学生模块无自动超级权限；不能将管理员user_id冒充employee_id |
| 客户/潜在客户 | identity_type=customer | 客户身份 | 当前学生接口不开放；客户在其他模块拥有同名工单权限也不能冒充学生调用 |
| 匿名访客 | 无有效登录身份 | 不产生学生Principal | 本模块34个接口均不允许匿名 |
| 同步服务/调度适配器 | 组长统一机器凭据，或可信进程内任务 | Principal(service, service_code, scopes) | HTTP同步需要student:sync；统一账号/YAML尚未支持该机器主体，需要单独确定接入方式 |

user_id是登录账号主键，student_id/employee_id是业务主键，不能按数值相等推断。组长同进程get_current_account可读取账号的业务关联字段；当前/me/access只返回用户ID、身份、权限及导航清单，不包含完整业务关联，HTTP接入时须由可信后端补充映射。

teacher是employee之下的业务资格，不新增一个未经组长确认的identity_type=teacher。服务凭据不能复用个人学生/老师登录身份，不能由前端自由指定service_code或scope。

## 三、统一鉴权总体设计

### 3.1 接入链路

~~~mermaid
flowchart LR
  A[客户端携带组长签发的Token] --> B[组长统一鉴权]
  B --> C[映射可信学生或员工身份]
  C --> D[检查接口权限]
  D --> E[检查记录归属和业务状态]
  E --> F[调用固定业务服务]
~~~

- 同一FastAPI应用优先复用组长app/core/auth.py的get_current_account及统一权限依赖；若组长明确要求HTTP校验，则使用他的指定接口，仍由他维护JWT规则。
- 组长负责登录、签名/有效期校验、账号身份及公共权限；学生模块保留资源归属、当前审批人、预警分派、版本、幂等与事务规则。
- 登录Token不传入Dify等无关外部服务；学生/员工ID不接受请求体、查询参数或X-Student-ID头覆盖。
- 鉴权服务不可用时按统一协议返回依赖错误，不降级成匿名，也不回退到旧学生自签登录凭证。
- 当前业务动作确认和会话绑定也使用签名凭证，接入统一登录时需单独拆分；它们不能代替登录验证或目标动作权限。

### 3.2 依赖的组长公共接口（不计入34个学生接口）

| 公共接口的目标挂载路径 | 作用 | 学生模块如何使用 |
|---|---|---|
| POST /api/v1/auth/login | 登录并获取Bearer Token | 前端使用组长登录能力，不新增学生独立登录接口 |
| GET /api/v1/auth/me/access | 查询统一身份、权限及页面/模块清单 | 前端展示入口；服务端仍须做接口与数据授权 |
| GET /api/v1/auth/public-access | 查询公开页面元数据 | 不代表学生业务接口公开 |

以上/api/v1是项目文档约定的目标前缀。auth.py自身前缀为/auth，当前main.py尚未挂载，最终外部路径以组长完成注册后的接口为准。统一机器鉴权方式尚待补充，不能假定上述个人登录已覆盖同步服务。

### 3.3 权限检查原则

允许访问 = 统一认证通过 AND 身份类型匹配 AND 具备接口权限 AND 记录/学生在授权范围 AND 业务状态允许。

前端按钮、页面清单和模块可见性只帮助展示；后端每个接口都必须验证。管理员默认不绕过心理数据与业务归属检查；本方案没有新增全体学生心理历史或全校审计接口。

## 六、请求、响应和业务状态约定

### 6.1 公共参数与身份规则

- 学生与老师接口携带Authorization: Bearer <组长Token>；同步接口携带组长认可的机器凭据。
- POST和DELETE写操作要求Idempotency-Key，8至128位可见ASCII，同一次提交重试复用原键；S21当前以已签名预览的稳定jti去重，不要求该HTTP请求头。
- 需要版本的写操作使用expected_version，读取真实详情后提交；版本变化返回冲突，刷新后由操作者重新确认。
- 列表limit默认20，范围1至100；offset默认0且不小于0。详情使用实际业务ID。
- 时间输入必须带明确时区偏移；后端转UTC。所有输入拒绝多余字段，不接收普通学生/老师请求体中的actor_type、student_id、employee_id等身份覆盖字段。
- M组请求体student_id是服务准备同步的目标学生，必须在机器凭据授权范围内，含义与前端自报登录身份不同。

### 6.4 错误约定：区分当前实现与统一接入

| 情况 | 现有学生实现 | 统一接入后的约定 |
|---|---|---|
| 缺少/无效登录身份 | 旧学生依赖通常为HTTP200、code=401 | 使用组长统一认证的HTTP401；错误体格式按组长公共协议 |
| 统一接口权限不足 | 尚未全面接入公共权限依赖 | 组长公共权限层HTTP403；业务归属校验仍保留 |
| 参数不合法 | HTTP200、code=400 | 保持学生业务约定，除非组长明确统一调整 |
| 记录不存在/非本人 | HTTP200、code=404，老师责任关系不符可能code=403 | 不通过错误详情泄露他人业务内容 |
| 幂等键内容冲突/旧版本/状态不允许 | HTTP200、code=409 | 保持冲突语义，不能自动覆盖或强行重试 |
| 数据服务/外部依赖不可用 | HTTP200、code=503 | 明确依赖不可用，不伪造AI/业务结果；统一认证依赖故障按公共协议适配 |

现有组长HTTPException响应可能是detail结构，并非学生信封；前端应同时处理HTTP状态与业务code。本文不宣称全组错误协议已经统一。

### 6.5 状态与事务规则

- 请假：submitted → approved/rejected/withdrawn。仅submitted可审批/撤回，驳回必须有意见；批准/驳回后学生不能撤回。双方引用同一apply_id，审批结果、操作记录、学生通知同事务提交。
- 工单：企业给出方案进入awaiting_student后，学生确认解决才closed；反馈未解决进入reopened并重新计算当前轮次期限；仅closed可评分。企业处理阶段由企业模块负责。
- 预警：pending → ack后processing → follow保持processing → close后closed。关闭必须先接手并写人工结果；读通知与接手、关闭是独立事实。
- 提醒：pending → queued → sent；本人可cancelled，恢复时需使旧消息代次失效；节点改期/取消重排提醒，用户已取消的设置不自动重开。
- 幂等：真实操作者＋动作＋逻辑请求键去重；相同参数回放原回执，不同参数409。回放也要重新确认当前账号/负责关系有效。
- 通知只投递本模块student.事件，站内sent表示进入相应收件人列表；不代表短信或企业外部渠道送达。

| 数据/动作 | 必须执行的限制 |
