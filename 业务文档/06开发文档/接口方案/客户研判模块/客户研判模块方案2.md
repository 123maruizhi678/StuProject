# 客户研判模块方案2

> 所属项目：粤教服务智能业务平台（粤教国际教育）
> 模块定位：面向**潜在客户**的多格式信息解析 + 画像规则研判
> 技术栈：Flask（后端）+ SQLAlchemy（ORM）+ 关系型数据库 + 向量数据库（RAG）+ 原生 JS（前端）
> 本文档 = 《客户研判模块方案》整体方案 + 《数据库设计文档》客户研判模块三张表设计的整合重构

---

## 1. 模块概述

客户研判模块是平台五大业务模块之一，核心目标是把**非结构化的客户信息**（自由文本、PDF 简历、Excel 表格）自动解析为**结构化字段**，再依据甲方《用户画像研判规则》对两个产品画像进行匹配研判，输出：

- 是否命中目标画像（`is_match`）
- 匹配等级（`match_level`：high / medium / low / none）
- 研判结论说明（`judgement_reason`）
- 命中 / 未命中的规则证据明细（`evidence`）

**关键特性**：未接入 Dify 时使用内置**本地规则引擎**离线完整运行；接入 Dify 后，AI 能力自动增强、失败自动回退本地规则引擎，保证服务永不中断。

## 2. 业务流程

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 输入  source_type(来源类型) + source_content(文本)        │
│          或  file(PDF/Excel/TXT 上传文件)                     │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. 文件落盘（若上传） → data/uploads/{uuid}.{ext}            │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. 解析  parse_source() → 结构化字段 fields                  │
│     文本：正则 + 关键词抽取                                   │
│     PDF ：pypdf 逐页提取文本后再抽取                          │
│     Excel：pandas 读为 CSV 文本再抽取（附列名/行数）           │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. （可选）Dify 结构化抽取增强 → 合并覆盖字段                  │
│    失败则静默回退本地抽取结果                                  │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ 5. 落库  customer_info（客户原始信息 + 解析字段）             │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ 6. 加载规则  judgement_rule（两个产品画像规则）               │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ 7. 逐规则研判  evaluate_rule() → 打分 / 等级 / 命中明细       │
│    （可选）Dify 研判覆盖 is_match / level / reason             │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ 8. 落库  customer_judgement（每个产品一条研判结果）           │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ 9. 返回结果（parsed_fields + judgements[]）                  │
└─────────────────────────────────────────────────────────────┘
```

## 4. 数据库设计（客户研判模块）

> 本节整合《数据库设计文档》第二部分「客户研判模块」的表结构定义。

### 4.1 设计总则

| 项目 | 说明 |
|------|------|
| 数据库类型 | 关系型数据库 + 向量数据库 |
| 字符集 | UTF-8 |
| 主键策略 | 自增 BIGINT |
| 时间字段 | DATETIME |
| JSON 字段 | 用于存储结构化扩展数据 |
| 向量字段 | 用于 RAG 检索（本模块当前未直接使用） |

### 4.2 客户信息表（customer_info）

**用途**：保存客户研判的原始输入及其解析后的结构化字段。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT | 主键 |
| source_type | VARCHAR | 来源类型（文本 / PDF / Excel） |
| source_content | TEXT | 原始内容 |
| parsed_fields | JSON | 解析后的结构化字段 |
| created_at | DATETIME | 创建时间 |

**字段说明**：

- `source_type`：枚举值 `text` / `pdf` / `excel`，标识客户信息来源载体。
- `source_content`：上传文本或从 PDF/Excel 提取后的原始文字，实现层截断至 5000 字。
- `parsed_fields`：结构化字段，典型结构如下：

```json
{
  "name": "张三",
  "phone": "13800000000",
  "email": null,
  "education": "本科",
  "target_country": "美国",
  "target_school": null,
  "keywords": ["留学", "申请"],
  "raw_snippet": "……"
}
```

### 4.3 研判结果表（customer_judgement）

**用途**：保存每个客户针对每个产品画像的研判结论，与 `customer_info` 一对多关联。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT | 主键 |
| customer_info_id | BIGINT | 关联客户信息 ID |
| product_code | VARCHAR | 产品编码 |
| is_match | BOOLEAN | 是否符合 |
| judgement_reason | TEXT | 研判原因 |
| created_at | DATETIME | 创建时间 |

**关联关系**：

- `customer_info_id` 外键关联 `customer_info.id`。
- 一条 `customer_info` 对应多条 `customer_judgement`（每个产品一条），即 `1 : N`。

### 4.4 研判规则表（judgement_rule）

**用途**：保存画像研判规则配置，按产品编码区分，规则内容以结构化 JSON 存储。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT | 主键 |
| product_code | VARCHAR | 产品编码 |
| rule_content | TEXT | 规则内容 |
| updated_at | DATETIME | 更新时间 |

**规则内容结构**（`rule_content` 内存储的 JSON 文本）：

```json
{
  "mode": "match_any",
  "threshold": 0.5,
  "conditions": [
    { "field": "education", "op": "in", "label": "学历达本科及以上", "values": ["本科", "硕士", "博士"] },
    { "field": "target_country", "op": "in", "label": "有明确留学意向国家", "values": ["美国", "英国"] },
    { "field": "keywords", "op": "contains_any", "label": "含留学相关诉求", "values": ["留学", "申请"] }
  ]
}
```

- `mode`：匹配模式（`match_any` 任一命中 / `match_all` 全部命中）。
- `threshold`：匹配阈值。
- `conditions[]`：规则条件集合（字段 + 操作符 + 标签 + 取值）。

### 4.5 表关系（ER 视图）

```
┌──────────────────┐       1 : N        ┌─────────────────────────┐
│  customer_info    │◄──────────────────│  customer_judgement      │
│  （客户信息表）     │  customer_info_id │  （研判结果表）            │
│  id (PK)          │                   │  id (PK)                 │
│  source_type      │                   │  customer_info_id (FK)   │
│  source_content   │                   │  product_code            │
│  parsed_fields    │                   │  is_match                │
│  created_at       │                   │  judgement_reason        │
└──────────────────┘                   │  created_at              │
                                        └─────────────────────────┘

┌──────────────────┐
│  judgement_rule   │  规则配置表，通过 product_code 与研判结果逻辑关联
│  （研判规则表）     │  （无外键，产品编码为业务关联键）
│  id (PK)          │
│  product_code     │
│  rule_content     │
│  updated_at       │
└──────────────────┘
```

### 4.6 设计文档 ↔ 代码实现对照

设计文档为抽象数据库设计；代码实现（`models/entities.py`）在其基础上做了少量工程化扩展。类型映射如下：

| 设计文档类型 | SQLAlchemy 实现 | 说明 |
|--------------|-----------------|------|
| BIGINT | Integer（自增） | 主键 |
| VARCHAR | String(n) | 定长字符串 |
| TEXT | Text | 长文本 |
| JSON | JSON | 结构化字段 |
| DATETIME | DateTime | 时间字段 |
| BOOLEAN | Boolean | 布尔字段 |

实现层扩展字段：

| 表 | 实现层新增字段 | 说明 |
|----|----------------|------|
| customer_judgement | `product_name` | 产品名称（展示用，避免联查） |
| customer_judgement | `match_level` | 匹配等级 high / medium / low / none |
| customer_judgement | `evidence` | 命中证据明细（score / matched / unmatched） |
| customer_judgement | `rule_version` | 所用规则版本 |
| judgement_rule | `product_name` | 产品名称 |
| judgement_rule | `version` | 规则版本（默认 v1.0） |

> 说明：设计文档中 `judgement_rule.rule_content` 标注为 TEXT，实现层以 JSON 类型存储结构化规则；语义一致，仅存储形式更规范。

## 5. 核心实现细节

### 5.1 输入解析（`utils/file_parser.py`）

统一入口 `parse_source(source_type, content, file_path)`，按类型分发：

| 类型 | 实现 | 说明 |
|------|------|------|
| text | `parse_text` | 直接对文本做字段抽取 |
| pdf | `parse_pdf` | `pypdf.PdfReader` 逐页 `extract_text()` 后抽取 |
| excel/csv | `parse_excel` | `pandas.read_excel` → `to_csv` 后抽取，附 `columns` / `row_count` |

字段抽取 `extract_fields()`（正则 + 关键词，尽力而为）：

| 字段 | 抽取方式 |
|------|----------|
| email | 正则 `[A-Za-z0-9._%+-]+@...` |
| phone | 正则 `1[3-9]\d{9}` |
| name | 优先匹配 `姓名：/ name：` 行，截取首个词 |
| education | 关键词命中（本科/硕士/博士/985/211…） |
| target_country | 关键词命中（美国/英国/澳洲…） |
| target_school | 匹配含「大学/院校/学校」的行 |
| keywords | 命中「留学/雅思/托福/背景提升/签证…」则收集 |
| raw_snippet | 前 500 字原文片段 |

### 5.2 规则引擎（`services/customer_service.py`）

#### 5.2.1 条件判断 `_check_condition(cond, fields)`

支持操作符：

| op | 含义 |
|----|------|
| `in` | 字段值包含 values 中任一（列表取交集，字符串做子串匹配） |
| `contains_any` | 同 `in` |
| `eq` | 字段值等于 values[0] |
| `not_empty` | 字段值非空 |

#### 5.2.2 规则评估 `evaluate_rule(rule_content, fields)`

```
score = 命中条件数 / 条件总数
mode = match_any → is_match = (score >= threshold)   # 默认 threshold=0.5
mode = match_all → is_match = (score >= 1.0)

等级判定（仅当 is_match 为真时）：
  score >= 0.8 → high
  score >= 0.5 → medium
  其余        → low
  is_match 为假 → none
```

### 5.3 AI 能力增强（Dify，可选）

```
dify.enabled = bool(DIFY_BASE_URL and (DIFY_API_KEY 或任一场景密钥))

1) 结构化抽取增强：dify.chat_json(...) 抽取字段，覆盖本地 fields
2) 研判覆盖：dify.chat_json(...) 依据规则研判，若返回含 is_match
   则覆盖 is_match / match_level / reason
任一环节异常 → logger.warning + 静默回退本地规则引擎
```

Prompt（`ai/prompts.py` 的 `JUDGE_PROMPT`）：

```
你是客户画像研判助手。请依据给定的画像规则，判断客户信息是否匹配。
输出 JSON：{"is_match": true/false, "match_level": "high/medium/low/none",
"reason": "命中/未命中的规则说明", "evidence": {...}}。
规则（JSON）：{rules}
客户信息（JSON）：{customer}
```

### 5.4 内置规则（演示数据 `scripts/seed.py`）

## 6. 接口方案

### 6.1 统一响应格式

所有接口返回：

```json
{ "code": 0, "message": "success", "data": { ... } }
```

- `code = 0` 表示成功；非 0 为业务错误码。
- 前端 `api.js` 统一解析：`code !== 0` 时抛出 `Error(message)`。

### 6.2 `POST /api/v1/customer/judge` — 提交客户研判

**功能**：解析客户信息并按全部画像规则研判，返回结构化结论。

**支持两种请求体**：

#### A. JSON（纯文本来源）

```http
POST /api/v1/customer/judge
Content-Type: application/json
```

请求体：

```json
{
  "source_type": "text",
  "source_content": "姓名：张三，本科，意向美国留学，电话13800000000"
}
```

#### B. multipart/form-data（文件上传）

```http
POST /api/v1/customer/judge
Content-Type: multipart/form-data
```

| 表单字段 | 类型 | 必填 | 说明 |
|----------|------|------|------|
| source_type | string | 是 | text / pdf / excel |
| source_content | string | 否 | 附加文本（文件来源时可补充） |
| file | file | 否 | 上传文件（.txt/.md/.pdf/.xlsx/.xls/.csv） |

> 文件扩展名校验：不在 `config.ALLOWED_UPLOAD_EXT` 白名单内则返回 400。
> 文件保存至 `data/uploads/{uuid}.{ext}`。

**响应示例**：

**curl 示例**：

```bash
# 文本来源
curl -X POST http://localhost:8000/api/v1/customer/judge \
  -H "Content-Type: application/json" \
  -d '{"source_type":"text","source_content":"姓名：张三，本科，意向美国留学，电话13800000000"}'

# 文件来源
curl -X POST http://localhost:8000/api/v1/customer/judge \
  -F "source_type=pdf" \
  -F "file=@/path/to/resume.pdf"
```

### 6.3 `GET /api/v1/customer/judge/{judgement_id}` — 查询单条研判

**响应**：返回该研判结果 + 对应客户的解析字段。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "judgement_id": 1,
    "customer_info_id": 1,
    "product_code": "P001",
```

```json
{
  "code": 0,
  "message": "success",

    {
      "id": 1,
      "product_code": "P001",
```

**参数**：`limit`（默认 20）。

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "customer_info_id": 2,
      "source_type": "text",
      "parsed_fields": { "name": "李四", "...": "..." },
      "created_at": "2026-10-15 12:00:00",

        { "product_name": "语言培训服务", "is_match": false, "match_level": "none" }
      ]
    }

}
```

## 7. 错误码与异常处理

| 错误码 | 异常类 | 触发场景 |
|--------|--------|----------|
| 400 | `BadRequestError` | 不支持的文件格式 / 客户信息解析失败 / 未配置研判规则 |
| 404 | `NotFoundError` | 研判结果不存在 |
| 500 | 全局兜底 | 未捕获的服务器异常 |

统一响应错误示例：

```json
{ "code": 400, "message": "不支持的文件格式：docx", "data": null }
```

## 8. 前端交互（`frontend/js/app.js` → `pageJudge`）

前端「客户研判」页面三块区域：

1. **提交表单**：来源类型下拉（文本/PDF/Excel）、文本输入框、文件上传、`开始研判` 按钮。
2. **画像研判规则**：调用 `GET /customer/rules` 展示两个产品画像及条件列表。
3. **研判记录**：调用 `GET /customer/records` 表格展示历史记录。

提交逻辑：

```js
// 有文件 → FormData 走 upload；无文件 → JSON 走 post
if (file) {
  const fd = new FormData();
  fd.append("source_type", type);
  fd.append("file", file);
  if (text) fd.append("source_content", text);
  res = await API.upload("/customer/judge", fd);
} else {
  if (!text) { toast("请填写文本内容或上传文件", "err"); return; }
  res = await API.post("/customer/judge", { source_type: type, source_content: text });
}
```

结果展示：解析字段摘要 + 每个产品的匹配徽章（符合画像 ✓ / 暂不符合 ✗）+ 匹配等级 + 研判结论 + 命中明细（可展开 `evidence` JSON）。

## 10. 扩展点与优化建议

1. **规则管理接口化**：当前规则仅支持查询（`GET /rules`），可扩展 `POST/PUT/DELETE` 实现规则在线配置与版本化。
2. **规则权重化**：`evaluate_rule` 目前按条件数等权计分，可扩展为加权打分（`conditions[].weight`）。
3. **字段抽取增强**：正则抽取较为朴素，可接入 NER / LLM 结构化抽取提升姓名、院校识别准确率。
4. **研判历史可视化**：`records` 可聚合为命中率、产品偏好等统计，联动数据看板。
5. **异步化**：大文件解析与 AI 调用可改为异步任务，避免长请求阻塞。
6. **文件清理**：上传文件落盘后未做生命周期管理，可增加定期清理或关联删除策略。
