# 客户研判模块 API、角色与权限清单

> 来源：`客户研判模块方案.md` 第 6 节“接口方案”及第 8 节“前端交互”。
> 说明：源方案定义了接口和业务操作，但没有定义登录认证方式、正式角色名称、用户身份模型或权限分配。下文将已明确内容与建议权限分开列出。

## 1. API 接口清单

所有接口采用统一响应结构：`{ "code": 0, "message": "success", "data": ... }`。`code = 0` 表示成功，非 0 表示业务错误。前端约定在 `code !== 0` 时按 `message` 展示错误。

| # | 方法 | 路径 | 功能 | 输入/参数 | 成功结果 |
| --- | --- | --- | --- | --- | --- |
| 1 | `POST` | `/api/v1/customer/judge` | 接收客户信息、解析字段，并按全部产品画像规则生成研判结果。 | JSON 文本请求；或 multipart 表单（`source_type` 必填，`source_content` 和 `file` 可选）。 | `customer_info_id`、`parsed_fields`、各产品的 `judgements`（含匹配状态、等级、原因和证据）。 |
| 2 | `GET` | `/api/v1/customer/judge/{judgement_id}` | 查询一条研判结果及客户解析字段。 | 路径参数 `judgement_id`。 | 研判与客户信息，包括产品、匹配状态、等级、原因、证据和 `parsed_fields`。 |
| 3 | `GET` | `/api/v1/customer/rules` | 查询画像研判规则。 | 无。 | 规则数组，含产品编码/名称、`rule_content` 和版本。 |
| 4 | `GET` | `/api/v1/customer/records` | 查询研判记录列表，按客户信息 ID 倒序，附各产品研判摘要。 | 查询参数 `limit`，默认 `20`。 | 客户记录数组，含来源类型、解析字段、创建时间和研判摘要。 |

### 1.1 提交研判：JSON 请求

```http
POST /api/v1/customer/judge
Content-Type: application/json
```

```json
{
  "source_type": "text",
  "source_content": "姓名：张三，本科，意向美国留学，电话13800000000"
}
```

### 1.2 提交研判：文件表单

```http
POST /api/v1/customer/judge
Content-Type: multipart/form-data
```

| 表单字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `source_type` | string | 是 | 来源类型：`text`、`pdf`、`excel`。 |
| `source_content` | string | 否 | 附加文本，文件来源时可一并提交。 |
| `file` | file | 否 | 支持 `.txt`、`.md`、`.pdf`、`.xlsx`、`.xls`、`.csv`，受 `ALLOWED_UPLOAD_EXT` 白名单约束。 |

文件保存至 `data/uploads/{uuid}.{ext}`。方案所述上传大小上限为 20 MB。扩展名不受支持时返回 400。

### 1.3 查询接口细节

- `GET /api/v1/customer/judge/{judgement_id}`：记录不存在时返回 404（`NotFoundError`）。
- `GET /api/v1/customer/rules`：返回画像规则配置；方案示例中包含产品编码、产品名称、匹配模式、阈值、条件和版本。
- `GET /api/v1/customer/records?limit=20`：`limit` 默认 20；方案未说明最小值、最大值或分页偏移参数。

### 1.4 错误码

| 错误码 | 场景 |
| --- | --- |
| 400 | 不支持的文件格式、客户信息解析失败、未配置研判规则。 |
| 404 | 研判结果不存在。 |
| 500 | 未捕获的服务器异常。 |

错误响应示例：`{ "code": 400, "message": "不支持的文件格式：docx", "data": null }`。

## 2. 源方案明确的用户与角色信息

源方案没有列出平台账号角色（例如管理员、员工或客户）、登录用户实体、身份字段、认证/鉴权机制，也没有声明上述接口是否公开。因此，无法从该方案抽取出已确定的“角色—用户—权限”授权表。

方案中可识别的业务使用者/参与方只有：

| 业务参与方 | 方案中明确的活动 | 是否为已定义的平台角色 |
| --- | --- | --- |
| 客户研判页面操作用户 | 在前端提交文本/文件，查看画像规则与历史研判记录。 | 否；方案未规定具体账号类型或角色名。 |
| 后端服务 | 解析输入、执行规则研判、保存客户信息及结果、返回响应。 | 系统组件，不是已定义的人类用户角色。 |
| Dify 工作流（可选） | 增强结构化抽取或研判；异常时回退到本地规则引擎。 | 外部服务，不是平台登录角色。 |

以上“页面操作用户”由前端交互内容归纳，属于业务使用者描述，不代表源方案已经设计了客户账号或任何授权策略。

## 3. 建议的最小权限映射（待产品/安全负责人确认）

为了便于后续接入统一鉴权，可按接口动作拆分权限。以下权限标识及角色映射是建议方案，不是源文件中已有的配置。

| 建议角色 | 建议用户范围 | 建议权限 |
| --- | --- | --- |
| `customer_judgement_operator`（客户研判操作员） | 经授权负责录入潜在客户资料、查看研判结果的业务人员。 | `customer.judgement.create`、`customer.judgement.read`、`customer.judgement.rules.read`、`customer.judgement.records.read` |
| `customer_judgement_viewer`（客户研判只读用户） | 仅需查看研判规则、结果和历史记录的人员。 | `customer.judgement.read`、`customer.judgement.rules.read`、`customer.judgement.records.read` |
| `customer_judgement_admin`（客户研判管理员） | 负责模块管理的人员；仅当后续增加规则维护等管理接口时配置。 | 当前四个接口的权限；未来规则写入权限应另行定义。 |

建议按以下关系保护接口：

| API | 建议所需权限 |
| --- | --- |
| `POST /api/v1/customer/judge` | `customer.judgement.create` |
| `GET /api/v1/customer/judge/{judgement_id}` | `customer.judgement.read` |
| `GET /api/v1/customer/rules` | `customer.judgement.rules.read` |
| `GET /api/v1/customer/records` | `customer.judgement.records.read` |

源方案中的“规则管理接口化”仅列为未来扩展方向，目前没有创建或更新规则的 API；不应据此授予规则写入权限。还需在实现时明确记录级数据范围、敏感客户资料访问审计，以及未登录请求的处理方式。

## 4. 方案配置项（与接口行为相关）

| 配置 | 环境变量 | 方案默认值 | 对接口的影响 |
| --- | --- | --- | --- |
| 上传目录 | `UPLOAD_DIR` | `backend/data/uploads` | 决定上传文件的落盘目录。 |
| 允许扩展名 | `ALLOWED_UPLOAD_EXT` | `txt/md/pdf/xlsx/xls/csv` | 限制文件接口可接收的类型；不在白名单时返回 400。 |
| 最大上传 | `MAX_CONTENT_LENGTH` | `20MB` | 上传请求体大小限制。 |
| Dify 地址 | `DIFY_BASE_URL` | 空 | 配置后启用 Dify 增强能力；未配置时本地规则可独立运行。 |
| 研判密钥 | `DIFY_KEY_JUDGE` | 空 | 客户研判场景密钥；未设置时可回退使用 `DIFY_API_KEY`。 |

以上环境配置来自源方案第 9 节；具体单位、解析格式及部署值应以最终应用配置实现为准。
