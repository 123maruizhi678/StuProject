## 2. 范围与执行原则

本期覆盖：客服对话、活动列表与详情、活动报名（写库 + 采集手机号）、课程列表、FAQ 兜底查询。

1. 客服Agent 为 7×24 无人值守咨询入口，降低访客咨询门槛，前 5 个接口维持匿名公开。
2. 全部接口统一走限流与审计；写库与采集个人信息的 `signup` 单独加强防护。
3. 员工、学生、报告等其它模块按各自进度接入 `authenticated` 鉴权，不在本模块范围。
4. 客服的课程、活动、报名、会话记录由客服模块管理；企业端转发留资只调用共享客户创建 service，不把报名人当作员工或学生。

## 3. 通用接口契约

### 3.1 路径、身份与数据范围

基础路径为 `/api/v1/agent`。以下接口清单省略此前缀。

系统统一抽象为 `Principal` 身份主体，采用 JWT（Bearer Token）认证，`Authorization: Bearer <token>` 传递，token 内含：

```json
{
  "sub": "主体唯一ID（访客可用匿名标识）",
  "type": "employee | student | visitor",
  "role": "advisor | student | anonymous",
  "scopes": ["agent:chat", "agent:signup", "enterprise:*"],
  "exp": 1730000000,
  "iat": 1729996400
}
```

- `type` 区分主体大类；`role` 细分角色；`scopes` 做细粒度接口权限。
- 员工/学生：登录后签发（含真实身份 + 权限）。
- 访客：**不强制登录**。首访时由后端签发一个 `visitor` 匿名 token，绑定 `session_id`，用于会话关联、限流计数与防刷审计。

| 访问级别 | 含义 | 适用 |
|---|---|---|
| `public` | 无需认证，但统一走限流与审计 | 客服Agent 全部接口 |
| `visitor` | 需访客匿名 token | 客服Agent 报名/留资（可选增强） |
| `authenticated` | 需登录（员工/学生） | 企业/学生/报告模块（非本清单） |

> 关键结论：客服Agent 在统一鉴权里是 **`public` 级别（公开访问）**，**不是**每个接口都要登录。它的防护重点在「限流 + 防刷 + 敏感数据脱敏」，而非身份认证。

### 3.2 请求与响应

- JSON 字段使用 `snake_case`；不序列化 ORM 全字段。
- 列表默认 `page=1, page_size=20`，`page_size` 最大 100；返回 `items/total/page/page_size`。
- 统一返回约定：鉴权失败返回 HTTP 401 + body `{"code": 401, "message": "未授权", "data": null}`（沿用 `ResultCode.UNAUTHORIZED`）。
- 报名接口**响应不返回**手机号明文，仅返回 `signup_id`。
- 写操作提交 `Idempotency-Key`（建议 UUID），`signup` 使用已有 `event_id + customer_phone` 唯一约束兜底幂等。

### 3.3 业务码

| code | 含义 |
|---|---|
| 0 | 请求已按契约处理 |
| 400 | 参数、枚举、时间或必填条件错误（如手机号格式） |
| 401 | 未登录、凭证失效（仅 `visitor`/`authenticated` 接口触发） |
| 403 | 无功能权限或超出数据范围 |
| 404 | 对象不存在 |
| 409 | 幂等冲突、业务唯一键冲突（如重复报名） |
| 429 | 触发限流（IP/接口维度） |
| 500 | 服务内部错误 |

`public` 接口不依赖登录，因此正常访问不会返回 401/403；429 由限流中间件统一返回。

## 4. 客服Agent 接口清单（全部 6 个）

下表「参数」列列出业务重点；通用分页、身份、幂等、版本与响应沿用第 3 节。接口均为已运行现状，目标态按「访问级别 / 防护重点」接入，不表示已加鉴权。

### 4.1 客服对话与公开查询（P0）

| 编号 | 方法 | 路径 | 功能、参数及返回重点 | 访问级别 | 防护重点 |
|---|---|---|---|---|---|
| AGT-01 | POST | `/chat` | `message/session_id`；客服对话，含会话/消息落库 | public | 限流（防刷 LLM 成本）、会话落库 |
| AGT-02 | GET | `/events` | 活动列表，参数 `keyword/page` | public | 公开信息，正常限流 |
| AGT-03 | GET | `/events/{id}` | 活动详情 | public | 公开信息 |
| AGT-04 | GET | `/courses` | 课程列表 | public | 公开信息 |
| AGT-05 | GET | `/faq` | FAQ 兜底查询，参数 `keyword` | public | 公开信息 |

### 4.2 活动报名（写库 + 采集个人信息，P0 加强）

| 编号 | 方法 | 路径 | 功能、参数及返回重点 | 访问级别 | 防护重点 |
|---|---|---|---|---|---|
| AGT-06 | POST | `/events/signup` | `event_id/customer_phone/name/...`；活动报名写库，返回 `signup_id`（不返回手机号明文） | public（可升级 visitor） | **强限流 + 防重 + 手机号校验 +（可选）验证码** |

规则：

- `signup` 是唯一的「写库 + 采集个人信息」接口，风险最高，单独加强：IP 限流、幂等（`event_id + customer_phone` 唯一约束）、手机号格式校验、可选图形验证码。
- 后续若接入 CRM / 客户统一管理，可升级为 `visitor` 或 `authenticated`。
- 报名/对话落库含手机号，DB 侧后续可加密存储（`customer_phone` 密文 + 检索 token），与统一「客户数据安全存储」要求对齐。

### 4.3 接口权限标识（scope）

| scope | 对应接口 |
|---|---|
| `agent:chat` | AGT-01 |
| `agent:events` | AGT-02 |
| `agent:events:read` | AGT-03 |
| `agent:courses` | AGT-04 |
| `agent:faq` | AGT-05 |
| `agent:signup` | AGT-06 |

客服Agent 整体可表示为 `agent:*`（覆盖以上全部 scope）。

## 5. 身份清单（系统全部主体）

系统统一抽象为 `Principal` 模型，共三类主体：

| 身份 | type | role | 来源 | 主要使用模块 | 默认持有的 agent scope |
|---|---|---|---|---|---|
| 员工 | `employee` | `advisor` | 企业登录后签发 | 企业智能助手、智能报告、后台管理 | 无（以 `enterprise:*` 为主） |
| 学生 | `student` | `student` | 学生登录后签发 | 学生智能助手 | 无（以 `student:*` 为主） |
| 访客/潜在客户 | `visitor` | `anonymous` | 匿名或留资（首访后端签发匿名 token） | **客服Agent** | `agent:*`（覆盖全部 6 个接口） |

> 说明：因客服Agent 全部接口为 `public`，从「能否访问」角度任意身份均可访问；但从「业务目标与授权 scope」角度，仅访客持有 `agent:*` 并作为目标用户。员工/学生并非本模块目标用户，其 `agent:*` 不应被默认签发。

## 6. 每个身份可调用的接口

### 6.1 依据、默认范围与阅读方式

身份来源为《客服Agent接口鉴权方案》统一鉴权总体设计。客服Agent 全部接口为 `public`，角色权限以本节具体规则收敛「是否需要登录 / 可访问范围 / 防护重点」，接口存在不代表所有身份都是其业务目标用户。所有路径均省略 `/api/v1/agent`。

规则：

1. 所有接口均为 `public` 级别，不强制登录；访客首访由后端签发匿名 `visitor` token，绑定 `session_id`。
2. 不设置隐式身份继承。访客的匿名 token 仅含 `agent:*` scope，不含任何企业/学生业务权限。
3. 允许一次接口调用，必须满足「访问级别 + 防护规则（限流/防刷/幂等/校验）」。`public` 不等于无限制，仅表示不要求登录身份。
4. 下表为功能入口许可，仍须检查限流、幂等、字段白名单与敏感数据脱敏。未列入默认或明确条件授权的写操作一律不开放。
5. 条件权限（如 `signup` 升级 `visitor`、验证码）是后端固定配置，不接受前端或 Dify 自报授权。

### 6.2 三个身份均可访问的公开入口

客服Agent 全部 6 个接口均为 `public`，因此**任意身份均可访问**；差异在于是否为业务目标用户及是否需要额外防护：

| 接口编号 | 方法与路径 | 访客/潜在客户（visitor） | 员工（employee） | 学生（student） |
|---|---|:---:|:---:|:---:|
| AGT-01 | POST `/chat` | ✅ 主用（`agent:chat`） | ✅ 可访问（public） | ✅ 可访问（public） |
| AGT-02 | GET `/events` | ✅ 主用（`agent:events`） | ✅ 可访问（public） | ✅ 可访问（public） |
| AGT-03 | GET `/events/{id}` | ✅ 主用（`agent:events:read`） | ✅ 可访问（public） | ✅ 可访问（public） |
| AGT-04 | GET `/courses` | ✅ 主用（`agent:courses`） | ✅ 可访问（public） | ✅ 可访问（public） |
| AGT-05 | GET `/faq` | ✅ 主用（`agent:faq`） | ✅ 可访问（public） | ✅ 可访问（public） |
| AGT-06 | POST `/events/signup` | ✅ 主用（`agent:signup`，强限流 + 防重） | ✅ 可访问（public） | ✅ 可访问（public） |

> 注：上表「✅ 可访问（public）」表示技术上可访问，但员工/学生**非本模块业务目标用户**；其主用接口在企业管理 / 学生智能助手模块，不应被默认签发 `agent:*` scope。

### 6.3 访客/潜在客户 `visitor`（本模块目标用户）

除公共入口外，持有 `agent:*` scope，可调用全部 6 个接口：

| 接口编号 | 方法与路径 | 数据范围/限制 |
|---|---|---|
| AGT-01 | POST `/chat` | 本人匿名会话（绑定 `session_id`）；限流 20 req/min/IP 防刷 LLM 成本 |
| AGT-02 | GET `/events` | 公开活动列表，正常限流 |
| AGT-03 | GET `/events/{id}` | 公开活动详情 |
| AGT-04 | GET `/courses` | 公开课程列表 |
| AGT-05 | GET `/faq` | 公开 FAQ 兜底查询 |
| AGT-06 | POST `/events/signup` | 写库 + 采集手机号；强限流 5 req/min/IP + 幂等（`event_id + customer_phone`）+ 手机号格式校验 +（可选）验证码；响应不返回手机号明文 |

认证：不强制登录；首访由后端签发匿名 `visitor` token，绑定 `session_id`，用于会话关联、限流计数与防刷审计。留资后可升级为真实身份，但业务上仍走 `public`/`visitor` 路径。

### 6.4 员工 `employee`

归属模块为企业智能助手、智能报告、后台管理（非客服Agent）。其 JWT 以 `enterprise:*` 为主，**不应默认持有 `agent:*`**。

| 能力 | 说明 |
|---|---|
| 公开接口可访问性 | 因客服Agent 为 `public`，员工身份**技术上可访问全部 6 个接口**，但不作为业务目标用户 |
| 默认 scope | `enterprise:*`（企业模块授权），不含 `agent:*` |
| 是否应签发 `agent:*` | 否，除非显式配置客服查看/运营用途 |
| 主用接口 | 不在本清单内（见企业管理模块接口方案） |
| 认证 | 登录后签发含真实身份的 JWT（authenticated 级别） |

员工不能因为可访问 `public` 客服接口，就获得任何客户留资、会话明细或学生/报告数据权限。

### 6.5 学生 `student`

归属模块为学生智能助手（非客服Agent）。其 JWT 以 `student:*` 为主，**不应默认持有 `agent:*`**。

| 能力 | 说明 |
|---|---|
| 公开接口可访问性 | 因客服Agent 为 `public`，学生身份**技术上可访问全部 6 个接口**，但不作为业务目标用户 |
| 默认 scope | `student:*`（学生模块授权），不含 `agent:*` |
| 是否应签发 `agent:*` | 否 |
| 主用接口 | 不在本清单内（见学生智能助手模块） |
| 认证 | 登录后签发含真实身份的 JWT（authenticated 级别） |

学生不能因为可访问 `public` 客服接口，就获得任何客户留资、会话明细或企业/报告数据权限。

### 6.6 多身份示例及权限验收

| 账号身份 | 可访问客服Agent | 备注 |
|---|---|---|
| 匿名访客（无 token） | 全部 6 个（受 public 限流） | 首访后端补发 visitor token |
| `[visitor]` | 全部 6 个（持 `agent:*`） | 本模块目标用户，signup 受强防护 |
| `[employee]` | 全部 6 个（public，技术可访问） | 非目标用户；主用企业接口，不应持 `agent:*` |
| `[student]` | 全部 6 个（public，技术可访问） | 非目标用户；主用学生接口，不应持 `agent:*` |
| `[employee, advisor]` + 显式 `agent:*` | 全部 6 个 | 仅当显式配置客服运营用途时签发 |

后续实现应验证：

1. 对 6 个接口逐一做访问级别检查；`public` 不要求登录但仍受限流与审计。
2. 列表、详情、报名、FAQ 均使用相同公开范围，不能从旁路泄露未授权数据。
3. 员工/学生即使可访问 `public` 接口，也不自动获得 `agent:*` scope 或客户留资权限。
4. 匿名访客 token 与 `session_id` 关联；留资后升级为真实身份不扩大接口权限。
5. `signup` 的限流、幂等、手机号校验对任何身份访问均生效，不可绕过。

## 7. 与其他模块的接口边界

| 模块 | 保留/复用接口能力 | 客服Agent 协作规则 |
|---|---|---|
| 企业管理 | 客户创建、员工/部门、日报、审批 | 客服留资调用共享客户创建 service，使用 `source_reference` 追溯，不直接把报名人当作员工或学生 |
| 学生智能助手 | 学生档案、请假、投诉、心理 | 客服不读取学生业务数据；活动/课程为公开信息 |
| 智能报告 | 报告生成与保存 | 客服对话/活动数据供数，不代生成正式报告 |
| 公共能力 | 认证（JWT）、限流、对象存储、通知渠道 | 复用实际公共服务；尚无最终契约的能力不编造服务地址和配置 |

客服的课程、活动、报名、公开 FAQ、访客会话由客服模块管理；企业端转发留资只调用共享客户创建 service。

## 8. 限流与防刷

| 维度 | 建议策略 |
|---|---|
| 全局 | IP 维度，如 120 req/min |
| AGT-01 `/chat` | 更严，如 20 req/min/IP（防止刷 LLM 调用成本） |
| AGT-06 `/events/signup` | 最严，如 5 req/min/IP + 幂等键 + 手机号校验（可选图形验证码） |

实现可选 `slowapi`（基于 limits），或自写基于内存/Redis 的滑动窗口中间件。多实例部署时用 Redis 集中计数。

### 8.1 敏感数据与审计

- 报名接口响应不返回手机号明文，仅返回 `signup_id`（当前已如此）。
- 报名/对话落库含手机号，DB 侧后续可加密存储（`customer_phone` 密文 + 检索 token），与统一「客户数据安全存储」要求对齐。
- 关键写操作接入操作日志（复用后续 `operation_log` 表思路），记录 IP、主体、时间、动作。

## 9. 实施顺序与验收建议

| 阶段 | 交付范围 | 验收重点 |
|---|---|---|
| 0 | 现状：接口无鉴权，仅靠数据库唯一约束防重 | 已完成 |
| 1 | 建统一鉴权基础设施：JWT 工具 + Principal + 中间件 + 401 handler | `app/core/security.py` |
| 2 | 客服Agent 接口接入 `public` 级别 + 全局限流 | agent 接口可安全暴露 |
| 3 | `signup` 加强：限流 + 手机号校验（+ 可选访客 token/验证码） | 防刷闭环 |
| 4 | 员工/学生/报告模块接入 `authenticated` 鉴权 | 全系统统一 |
| 5 | 敏感数据加密存储 + 操作审计 | 合规收尾 |

建议验收场景：

1. 匿名访客首访自动获得 visitor token，可完整走完对话、查活动、报名流程。
2. `chat` 与 `signup` 触发各自限流阈值后返回 429，且不泄露后端错误细节。
3. 相同 `event_id + customer_phone` 重复报名返回 409，不重复写库。
4. 员工/学生可访问 public 客服接口，但其 JWT 不含 `agent:*`，也不能读取客户留资明细。
5. 报名响应不含手机号明文；审计日志记录 IP、主体、时间、动作。

## 10. 请确认的方案选择

建议按以下默认选择确认；可直接指出需要调整的条目：

1. **范围**：客服Agent 6 个接口全部 `public`，仅 `signup` 可升级 `visitor`；不要求登录。
2. **身份主体**：统一 `Principal`，含 `employee` / `student` / `visitor` 三类；访客首访签发匿名 token。
3. **权限 scope**：仅访客默认持有 `agent:*`；员工/学生不默认持有，避免越权访问客服数据。
4. **防护重点**：限流 + 防刷 + 敏感数据脱敏；`chat`/`signup` 单独收紧。
5. **接口风格**：沿用现有路径与响应契约；统一 401/429 信封，不切换协议。
6. **渐进落地**：先建统一鉴权基础设施，再把客服Agent 一次性接入 `public`；内部模块按各自进度接入 `authenticated`。
